# 信息冲突与过期诊断助手 · 前端设计方案

日期：2026-10-04。状态：视觉与页面结构提案，待确定；本轮不编写前端代码、不接入后台。

## 1. 定位与边界

主题为“信息冲突与过期诊断助手”。初始示例场景采用高校通知、补充说明与转发材料；产品是否限定这一场景，待用户进一步确定。当前不锁定查询方式、数据源、上传格式、账号体系或诊断算法。

产品名称用“信息核对助手”暂代。主标题：“多份信息，核对清楚再行动。”说明：“对照时间、条件与适用对象，查看信息差异和判断依据。”不使用“自动辨真伪”或“保证最新”等无法保证的宣传。

目标用户：面对多个来源、不同版本信息，需要确认行动要求的学生与其他信息使用者。采用自定义“研究工作台”视觉系统：浅色资料式排版、稳定网格、逐项对照、证据注释。现无既定品牌参考，名称和标识后续可替换。

设计校准：布局变化4/10，动效2/10，首页密度4/10、核对页密度7/10，素材依赖2/10，品牌约束2/10。保持稳定导航，把视觉重点集中在差异对照上。

## 2. 页面结构

### A. 首页：说明用途并开始核对

顶部：文字标识、开始核对、示例案例、关于作品。保持四个以内的导航入口。

主体：两行以内主标题、一句说明、大输入区域、主按钮“开始核对”。输入提示：“描述你想确认的事项，例如截止时间、适用对象或材料要求。”

资料加入区紧随输入区域。呈现可添加多个来源的结构，但网址、文本、文件中的实际支持方式待定；原型只演示明确选定的一种方式，不摆放无效功能按钮。

下方展示三个明确标注的演示案例：报名截止时间不同、原通知与补充通知要求不同、不同对象适用不同条件。再用三个简短步骤解释“加入资料 → 对照差异 → 查看依据”。

首页不展示虚构的核验数量、准确率、机构背书或用户评价。底部说明作品性质与能力范围，不使用政府徽标或仿官方身份。

### B. 核对工作台：作品的主要页面

桌面采用左侧资料栏、中央对照区、右侧依据栏。

左侧约240px：本次核对事项与来源列表。每条来源显示标题、发布主体、发布日期、获取时间或状态。发布日期缺失时写“未提供”，不能以获取时间代替。资料选中状态与添加入口清晰可见。

中央弹性区域：顶部显示当前问题与简短结果概览，主体是逐项对照表。

对照表示例结构：核对项目 / 来源A表述 / 来源B表述 / 差异说明。示例核对项目为截止时间、适用对象、提交材料、办理入口；真实项目由后续功能决定。来源超过两份时默认选两份比较，其余通过选择器切换，避免横向无限堆列。

点击任一差异行，右侧显示对应原文与位置。差异文字采用局部标注，重点突出日期、对象或条件；不把整篇原文染色。

右侧约320px：依据与限制。显示来源标题、原文片段、页码或章节位置、原始链接，以及当前结论还有哪些条件未确认。提供“查看原文”入口；全文在展开面板中阅读，避免挤占对照空间。

结果概览暂定采用可解释的文字状态，例如“发现时间差异”“适用对象不同”“可能存在后续更新”“证据不足，待确认”。状态名称与判定规则待功能确定，不先设计一个伪精确的可信度百分比。

### C. 来源详情与时间线

来源详情先采用侧面板，包含发布主体、发布时间、适用时间、获取时间、原始地址和可用正文位置。需要长文阅读时再扩为独立页面。

时间线作为工作台内可选视图：按已知发布日期显示原通知、补充说明等材料。缺日期资料单独列出；排序只表示时间先后，不自动意味着新版覆盖旧版。

### D. 示例案例与关于作品

示例案例页提供三组清晰的小案例，进入同一工作台。模拟材料明确标为模拟，真实公开材料保留出处。

关于作品页说明适用范围、资料来源与已知限制。评估方法待功能确定后补充，匿名评审版不展示团队和学校身份，按赛事要求执行。

## 3. 视觉系统

| 项目 | 定义 |
|---|---|
| 背景 | 暖白 #F7F8F5 |
| 内容表面 | 白色 #FFFFFF |
| 主文字 | 石墨色 #202B33 |
| 次文字 | #596774 |
| 交互主色 | 深蓝 #234E67，用于主按钮、链接与当前选中项 |
| 分隔线 | #DDE3E4 |
| 差异标记 | 琥珀色 #815C19 表示需关注，砖红 #A0443D 表示明确差异；必须同时提供文字标签 |
| 中性状态 | 灰色用于未知，深蓝用于当前依据；不能用绿色直接表示信息为真 |
| 字体 | 中文标题采用思源宋体或 Noto Serif SC；正文采用思源黑体或 Noto Sans SC；提供系统回退 |
| 字号 | 桌面主标题44—48px，手机32px；页标题28px；正文16px，行高1.65；元数据13—14px |
| 间距 | 4、8、12、16、24、32、48、64px |
| 网格 | 最大内容宽1360px，桌面边距32px，手机16px，主体栏距24px |
| 圆角 | 内容面板与输入框8px，按钮6px，标签4px |
| 阴影 | 正文以细线分隔；浮层使用单层轻微阴影 |
| 动效 | 状态切换与展开120—180ms，尊重减少动态效果设置 |

视觉主角是原文差异和来源关系。采用行式资料结构，少量面板组织内容，不做满屏统计卡片。首版不需要大型插图；必要时再用 gpt-image-2 制作辅助素材。

字体优先系统回退，按需自托管裁剪字体，避免字体加载阻塞首屏。原文和结果保持可选择、可复制。状态与差异不能只靠颜色区分。

## 4. 响应式与阅读条件

1360px及以上：三栏完整展示。1024—1359px：右侧依据改为抽屉，中央对照保持主导。1024px以下：单栏或双栏，根据可用宽度逐步收起来源列表。

手机：事项输入 → 来源列表 → 差异摘要 → 逐项对照 → 依据。对照表转换为按项目排列的来源对照块，避免迫使用户横向阅读整张宽表。查看依据通过明确按钮触发，不能仅依赖悬停。

首页用于快速理解，工作台用于长时间阅读，因此正文可读性优先于大面积装饰和动效。

## 5. 状态与交互

骨架覆盖：尚未加入资料、资料待处理、处理中、有差异、未发现差异、部分资料不可用、无法判定、服务错误。

“未发现差异”只表示当前资料范围内没有找到差异，不表示信息真实、完整或仍有效。日期过早也不能单独作为失效依据；页面需要容纳生效期、适用条件与证据不足状态。

原型阶段所有材料、判断与过程明确标注演示用途。真实处理中只展示后台确实发生的阶段，不展示虚构智能体执行或内部思考。

选中差异行时更新对应依据；原文支持展开全文。添加或移除资料后，旧结果若仍显示，需要明确提示其尚未重新核对，避免用户误读。

错误信息提供下一步动作：补充资料、修改事项或重试。保留有效输入和可用资料。键盘可操作输入、来源选择、对照行与抽屉；焦点可见，输入有标签，图标按钮有名称。

## 6. 现在确定与保留

建议本轮确定：浅色资料工作台、首页直接开始、来源与差异相邻、右侧原文依据、手机逐项对照、低动效。

待用户思考：目标场景、资料加入方式、是否自动检索、支持格式、过期与冲突判定规则、更新时间、历史记录、导出和通知。前端采用可替换模块，不用尚未确定的功能填满页面。

## 7. 后续交付

设计方向认可后，再制作可浏览的前端v0：一个首页、一组演示材料的核对工作台、来源详情和关键状态。先确认布局和视觉，再根据确定的功能完善交互与接口。

既有 React + Vite、FastAPI、SQLite 与 Docker 方案可继续保留。旧《网站实施方案》中科研文献功能和日程交付项已经不是当前主题，应在功能明确后统一重写；当前以前端设计方案中的信息冲突与过期诊断定位为准。
