项目根目录的复测命令（网络可访问时）：

```powershell
.\.venv\Scripts\python.exe tools\probe_satwiki.py --output artifacts\satwiki-access-probe
```

脚本最多请求 robots 与一个元数据接口；明确禁止 API 的 robots 规则、限流、API 403或异常响应都会记录并停止。robots 未验证时仅尝试元数据诊断，不允许据此执行词条枚举或下载。

### API 的访问条件

灰机《帮助:Python》明确说明：因反爬虫策略，自定义请求访问 API 需要向职员申请额外的 `authkey`；页面同时介绍 `mwclient` 和推荐声明工具名称、版本、联系方式的 User-Agent。[帮助:Python](https://www.huijiwiki.com/wiki/帮助:Python)

本次查到的该文档没有给出可以可靠照抄的 `authkey` 传递方式。不要猜测它是 query 参数、Header 或 Cookie；应以平台提供的接入说明为准。账号登录与这个额外凭据不能视为同一件事。

### 官方数据更新器的可执行试用流程

获得平台认可的访问方式后，可在官方页面核对程序来源，选择目标站点，在“批量操作页面”中用少量标题名单选择词条，评估“保存源代码到文本”输出。历史官方更新日志说明，程序可将选中页面源代码保存成 `.wiki` 文件。[2017 年更新日志](https://www.huijiwiki.com/wiki/帮助:灰机Wiki数据更新器/更新日志/2017年)

这条路径首先验证只读导出；工具同时存在编辑、上传和刷新功能，知识库采集不需要这些操作。原始 Wikitext 文本不能保证已经包含展开后的参数表或模板正文。

## 备份与 AI 文档要分别保存

`Special:Export` 的 XML 保存的是 Wikitext，而非页面显示的 HTML；缺失模板会导致重新渲染不完整。导出历史有助于保留署名信息，但不能假定一次请求能完整获取所有修订。[Help:Export](https://www.mediawiki.org/wiki/Help:Export)

知识库整理时建议保留原始 Wikitext，同时在 API 获准且支持的情况下用 `action=parse` 获取渲染输出。MediaWiki 的 parse 模块可以按页面或修订 ID 解析，并返回 HTML、引用模板、章节、外链等信息；从 HTML 清洗出正文与表格，比只删除 Wikitext 标记更有利于保留模板展开内容。这是处理建议，未验证卫星百科上具体模板或动态内容的完整性。[API:Parsing wikitext](https://www.mediawiki.org/wiki/API:Parsing_wikitext)

API 方案还可用 `list=categorymembers` 选取分类成员并处理继续分页，用 `prop=revisions` 获取版本 ID、时间、作者及内容；具体参数应以目标站点支持的版本为准。[API:Categorymembers](https://www.mediawiki.org/wiki/API:Categorymembers) · [API:Revisions](https://www.mediawiki.org/wiki/API:Revisions)
