# 新闻阅读页与许可分层方案审核意见

日期：2026-10-05。对象：docs/plans/新闻阅读页与许可分层实施方案.md。仅审核方案与当前代码，不修改功能、获取新闻全文/图片、变更授权或操作OSS。

用户后续明确选择弹窗阅读；方案已调整为扩展现有dialog，不另开独立页面。下面页面/导航意见按弹窗状态管理理解，许可与撤回方面的风险不因展示容器改变。

## 结论

方案总体可行，现有FastAPI、SQLite、纯JavaScript和OSS足以支持。连续阅读弹窗、分层展示、少量真实样本、服务端内容过滤、安全结构块、保留原新闻身份与后续AI上下文边界方向正确，不必先引入新的数据库、前端框架或常驻浏览器。

主要外部依赖是许可依据与样本核对；主要技术风险是撤回后仍能访问的素材地址和缓存。目标2—3个工作日适合作为基础阅读页及有限样本的理想工期，不能包含无法控制的授权等待，也不应同时承诺327篇自写导读或全部来源全文。

## 许可调查的实际难点

NASA当前媒体指南允许符合条件的教育、信息和事实性使用，并要求来源说明；NASA获准使用的第三方素材不因此对别人转授权。该页主要针对媒体素材，不能仅凭此入口就把每篇NASA新闻正文或APOD图片统一放行。3—5篇样本建议从明确署名和来源的NASA自有新闻内容调查起，保留正文与逐图各自依据。[NASA媒体指南](https://www.nasa.gov/nasa-brand-center/images-and-media/)

ESA网站条款对个人非商业阅读/下载与再发布作了区分，再发布不能仅凭个人阅读许可；图片/视频条款则为符合条件的教育、新闻与信息用途提供具体使用范围，同时要求credit及第三方权利核对。两类材料分开授权/审核是必要的。[ESA网站条款](https://www.esa.int/Services/Terms_and_conditions)、[ESA多媒体条款](https://www.esa.int/ESA_Multimedia/Terms_and_conditions_of_use_of_images_and_videos_available_on_the_esa_website)

中国载人航天影像说明涉及允许使用及二次加工，不能将其扩展为新闻文字的通用许可；获取允许也不等于可以任意裁切、压缩或改变带科学信息的图表。[官方影像说明](https://www.cmse.gov.cn/dmt/bqsm/)

著作权法区分单纯事实消息与作品表达；适当引用有用途、署名及权益条件，并非固定字数安全线。课堂/科研使用的相关例外也不能直接替代公众网站再发布的用途判断。具体样本依实际内容及使用方式核对，不作全部节选当然可用的结论。[国家版权局著作权法第五条、第二十四条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

许可调研记录应包含已核对条款原文位置/公开地址、核对时间、证据摘要与版本；私人授权文件、签名和联系方式独立保存，公开API只返回必要使用说明，不原样暴露完整授权文件。

## 撤回与缓存要写成可实现目标

当前resources.py为PDF和封面固定校验public/与public/covers/，不能直接当成新闻图片通用通道。新闻图像访问模块另建，域名/前缀/对象权限经用户确认；仅换前缀不等于访问权限隔离。

OSS公开对象可通过固定URL访问，私有对象使用有期限的签名URL。因此“API不再返回图片”不等于“原图片地址无法访问”；若要求可撤回，不适合默认永久公开地址。[OSS固定与签名URL说明](https://www.alibabacloud.com/help/en/oss/use-a-fixed-file-url-to-access-a-file)

首版建议content接口和敏感阅读响应使用no-store，不新增离线全文/Service Worker缓存；若未来使用ETag，需把当前许可/素材状态纳入验证。收到撤回后所有内容读取、旧版本接口、素材地址生成和内部AI材料函数走同一个当前许可检查。许可字段变化要有受控维护命令、审计记录和原子发布/下架流程，不开放公众写权限。

保证未来请求停止提供及受控链接在规定时间内失效，是可验收目标；已经到达读者设备的正文、截图或下载无法由服务器完全收回。把这个边界写明，避免“任何旧缓存都立即消失”的不可实现承诺。[OSS/CDN缓存与鉴权配置](https://www.alibabacloud.com/help/en/oss/user-guide/cdn-acceleration)

列表与原/api/news/{id}也必须受审查状态约束：撤回正文时若旧summary含相关原文摘录，不能只处理新/content接口而继续从旧接口输出。不同文本用途可独立判断，不能一刀切把所有许可都视为同一种权限。

## 建议补充的数据和接口约定

- 许可记录：不可变版本、依据类型、适用文章/素材、允许操作与用途、核对人/时间、有效期及撤回/失效原因。人工修订保留历史，但公共读取只使用当前有效版本。
- 导读记录：guide_kind、编辑者/审核时间、来源材料ID及版本、是否含引用；获取失败不触发随意编写导读，也不自动调用LLM。
- 内容记录：源地址、抓取时间、源快照hash、语言、结构块及版本、完整性核对结果；审查原始HTML/完整快照若留存，需有允许的存储依据并保持私有，不能放入web/或公开静态资源。
- read_scope枚举建议guide/full/withdrawn/unavailable；另有获取状态pending/ready/partial/failed。许可允许但获取失败，不输出full；部分图片不可用也不等于文字读取失败。
- /content第一次读文章404、内容未就绪/导读/撤回状态及图片状态应有固定合同；旧客户端的元数据接口不附全文。选词/段落接口本轮不开放任意文字作为AI上下文。
- AI上下文现在只预留函数合同和测试，不调用模型。将来ai_context_permission要注明允许的处理类型、外部模型服务范围等，不等同于训练许可；服务端持有未确认正文也不等于允许送模型。

## 工期与分阶段建议

1. 阅读弹窗基础：扩展现有dialog、保持列表状态、弹窗深链接与关闭/Esc/焦点、轻量元数据和范围标记、内容DTO、安全块渲染、自有测试内容；授权未明文章保持原文入口。
2. 许可与样本：核对3—5篇；先通过一篇纯文本全文、一篇图文样本及一篇导读/元数据回退。未找到权限清楚的真实例子，不以模拟稿替代对外验收。
3. 发布与撤回：允许操作的许可版本、独立图像存储、短期访问和缓存策略；用自有样本测试撤回、超限、失败、版本切换与竞态。
4. 上线回归：327条原数据、来源状态、旧历史任务与失败队列、OSS电子书下载、新闻调度、手机阅读、复制链接/刷新/前后退及重建/独立恢复。

复用现有弹窗可减少独立页面切换工作，但长文滚动、手机显示与键盘交互仍需验证；许可、全文保真、OSS访问和撤回核对工作量保持。授权等待独立计算。2核2G在有限样本、图片直达OSS、无OCR/模型调用的范围内没有明显架构障碍，内存与流量仍按实际样本测量。

整体建议：补齐上述约定后实施，优先少量许可清楚样本和阅读体验，不把所有来源全文放行当成前置条件。本轮仅审核，没有执行来源获取、代码改造或部署。
