# 新闻配图首轮采集修复

2026-10-07。用户服务器首轮结果：352 failed、349 unconfirmed、350 failed。已从公网 API 核对对应标题和原文地址。

## 已复现的原因与修复

- 352、350 是 science.nasa.gov 的 `/earth/earth-observatory/` 栏目，旧路径白名单没有覆盖，请求在网络访问前就拒绝。已仅为该主机增加这个新闻路径，不开放所有 NASA 子域或任意路径。
- 349 官方署名是 `Credit: NASA/Jessica Meir`，旧规则只匹配纯 NASA。依据 [NASA 官方人物资料](https://www.nasa.gov/people/jessica-u-meir/)，增加这条具体、经过核对的 NASA 创作者署名，保留完整署名；没有用 NASA/* 通配放行合作者。
- 349 实际 NASA 媒体布局为外层 hds-media、内层 figure、同级 figcaption，旧程序只找内层 figure，漏掉关联署名。已按真实结构修复并增加回归。
- 实际图片在官方 images-assets.nasa.gov 图片库。旧主机规则漏了该 CDN，现只允许 HTTPS 的 `/image/项目ID/图片文件`，拒绝正文访问、无关路径、伪域名和穿越。删除 CDN 画面裁切/缩放查询参数，使用对应文件再等比例缩小。
- 原错误提示过于笼统，现返回固定错误代码：路径、主机、非公网 DNS、robots、HTTP 状态和网络/文件问题等，不写出原始异常中的敏感数据。
- 新增 inspect（只读文章 HTML，统计候选和署名，不下载图片）与 retry（明确单条重试，保留权限规则；已撤回的图片拒绝重试）。自动冷却规则不变。

已直接读取 349 的真实官方 HTML，确认现在产生 1 个候选，署名完整。尚未从生产下载并保存该图片，不能将候选解析成功写成服务器 ready。350、352 路径问题已修，可能仍因无可确认署名保持 unconfirmed，不能为提高覆盖率伪造 NASA 署名。

```bash

```

inspect 预期 inspected 且 confirmed_candidates 至少 1；retry 会下载并保存图片，成功才显示 ready。如图片库 DNS、robots 或 HTTP 请求受限，返回具体错误，不绕过。ready 后刷新网页查看这一条新闻的右侧图片。

也可以按需 inspect/retry 352、350。不要反复运行 collect 来替代单条重试：collect 会跳过六小时冷却内的旧失败条目，并选其他待处理条目。先确认至少一条从获取到展示完整通过，再开启自动采集。

回退时恢复代码和原镜像标签后重建，保留现有运行数据。记录中的成功候选不代表对整个 NASA 图片库的权利审查；第三方、APOD 和未经核对的创作者规则仍维持。
