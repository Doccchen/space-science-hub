# 人工审核与服务器新闻图片部署

更新：2026-10-06。用户最终选择：单管理员；图片保存服务器持久卷并从本站直接加载。新闻图片不使用OSS，也不需要提供AccessKey；原有PDF的OSS下载配置保留。政府来源仍逐篇许可，其他机构和企业继续原文阅读。AI不实现。

脚本暂停审核服务和新闻采集，在旧容器生成SQLite＋引用图片联合快照，再构建运行回归、保留新闻/队列/来源状态、同卷重建验证。v5附加账户、会话、草稿、任务、图片及审核日志表；不删除历史记录。失败恢复旧镜像和原采集状态，联合备份留在`review-upgrade-时间/joint-before`和数据卷`review-backups/时间`中。

首次部署后人工设置管理员。为避免初始化与采集抢锁，先暂停采集，设置后恢复：

```bash

docker compose exec app python -m tools.admin_user --username admin
docker compose --profile review up -d --no-deps admin
COLLECT_ENABLED=1 docker compose up -d --no-build --no-deps app

```

密码通过终端交互输入两次，不回显，不发送到聊天。若原采集状态为0，最后一条保持0。命令也可用于重设密码，会撤销旧会话。不存在默认密码；请不要在公网HTTP入口输入管理员密码。

## 2. 打开后台

后台服务只在服务器`127.0.0.1:8090`监听，不新增公网端口或修改防火墙。本机另开PowerShell窗口，保持下面SSH连接运行：

```powershell
ssh -i "D:\Documents\竞赛\AI+信息素养\GPT.pem" -N -L "127.0.0.1:18080:127.0.0.1:8090" root@8.137.164.100
```

国内浏览器打开`http://127.0.0.1:18080`，登录刚设置的账号。后台会话1小时，5次登录失败锁定10分钟，HttpOnly/SameSite会话、Origin和CSRF检查启用。若要改本机端口，需要同步.env中的ADMIN_ORIGIN，再重建admin服务。

## 3. 审核正文与图片

1. 在政府新闻队列选择现有文章，点击“抓取待审核正文”。只抓原登记文章及已审主机/路径；任务在后台处理，不自动产生转载许可。失败记录原因并保留历史，可检查后重试。
2. 打开原文逐段核对正文、顺序、数字和限定语；编辑正文/署名，填写正文权利人、许可依据、第三方例外、有效期和公开说明。确认允许本站公开展示及完整性后，“审核通过并发布”直接发布当前版本。修改冲突或切换文章时必须重新核对；撤回后重新发布需另勾选。
3. 图片候选来自此草稿的文章。正文发布后逐图查看原图，填写图注、credit、权利人、许可依据和例外，重新选择当前正文的显示位置，确认图片对应文章与使用范围，再点击抓取保存。
4. 每正文版本最多5张，每张8MiB、2400万像素以内，仅JPEG/PNG/WebP且格式与响应一致，不做裁剪、压缩或OCR。后台单任务处理；磁盘不足256MiB余量拒绝写入，保留数据库空间。只使用合法公开获取方式，不绕过robots、登录、地区封锁或安全检查。
5. 成功后图片保存在`/data/news-images/文章ID/图片ID/哈希.格式`，当前阅读弹窗直接从本站图片接口加载，带图注/署名，失败显示原文提示。该目录不是静态挂载，其他来源、旧版本、撤回/过期图片不提供访问。

抓取/保存任务状态自动刷新，正文编辑区需“重新读取审核状态”才能加载新抓取稿，以免覆盖正在编辑的内容。修改正文后需保存并重新发布，再按当前版本确认图片位置。历史图片保留私有文件，不混入新正文。

后台可以撤回正文或单图。新图片请求立即按当前许可检查并拒绝已撤下内容；打开的阅读弹窗最多30秒复查一次。已显示、已下载的材料无法从读者设备追回。

## 4. 联合备份与恢复

暂停两种写入者后生成联合备份（不要在仍运行的审核工作线程旁直接复制图片）：

```bash
docker compose --profile review stop admin
COLLECT_ENABLED=0 docker compose up -d --no-build --no-deps app
docker compose exec -T app python -m tools.backup_review backup /data/review-backups/manual-20261006
docker compose --profile review up -d --no-deps admin
COLLECT_ENABLED=1 docker compose up -d --no-build --no-deps app
```

备份目标必须空，每次更换名字。备份含数据库、全部登记图片、SHA256清单，并包含私有草稿/账户哈希/审核日志；不要提供公开下载。

独立恢复工具：`python -m tools.backup_review restore /新卷目录 --source /备份目录`。只允许空目标，先校验数据库与每幅图片校验和，再恢复。用新命名卷挂载该目录并设置所有者10001:10001，在隔离服务核对身份/队列、正文版本、图片内容、审核状态；原卷保留，核对后再切换，不覆盖运行中数据库或只恢复SQLite而漏图片。

禁止`docker compose down -v`。镜像回退不删除附加表或文件；旧镜像没有后台或图片功能，回退期间停止审核服务。

## 5. 服务器人工验收

确认app与admin均健康，admin端口只有127.0.0.1:8090；公网新闻网站不能访问后台API。通过转发登录后，选一篇政府文章验证抓取草稿不公开、填依据后发布可读、未确认不能通过、草稿版本冲突提示、撤回后停止输出。

图片须在国内服务器实际抓取一个已核对许可样本，确认任务done、本机图片文件与公开展示一致、图注和credit正确；重建admin/app后仍在；撤回单图后访问旧图片入口返回404；数据库＋图片在独立目录恢复后可读。代码测试中的自有小图片不进入生产新闻。
