# 新闻阅读弹窗部署与验收

更新2026-10-06：政府候选经逐篇许可核对后展示全文；ESA与企业只提供标题、来源/日期、原文链接，不展示摘要、正文或配图。旧导读停止公开，保留历史内容。

本轮正文与弹窗；用户明确排除全部AI功能，并选择图片待私有存储配置后接入。现有PDF下载存储不变。服务器在国内，由用户执行部署，Git提交与推送由用户处理。

## 2. 服务器升级

```bash
set -e
cd /opt/space-news
stamp=$(date -u +%Y%m%dT%H%M%SZ)
tar -czf "/root/space-news-before-reading-$stamp.tar.gz" --exclude='./data' --exclude='./.git' --exclude='./.venv' --exclude='./artifacts' --exclude='./.env' --exclude='./*.pem' -C /opt/space-news .
tar -xzf /root/space-reading-release.tar.gz -C /opt/space-news
bash tools/upgrade_reading.sh
```

脚本暂停采集，保存一致性SQLite备份与原镜像ID，构建并运行回归测试，导入与既有新闻URL匹配的有限样本，再强制重建容器验证数据及阅读版本仍在，最后恢复原采集状态。已有阅读版本或撤回状态不会被重跑部署覆盖。没有匹配新闻的样本记为article_missing，不创建伪新闻或偷偷补抓。

输出保存在`/opt/space-news/reading-upgrade-时间/`，数据库备份为其中`before.sqlite3`；同卷`/data/reading-acceptance/`也保留证据。备份含历史内容，不要公开提供下载。env-backup权限600，不打印环境文件。

基础通过条件：健康、旧新闻身份/回填队列/来源开关不变、许可过滤正确、资料28项与24封面/下载跳转正常、重建后阅读版本相同。真实样本另外标记sample_acceptance：至少3篇政府全文可显示时才为passed；ESA及企业另检查三类API的link_only边界；正文样本缺失、未导入或已撤回则为incomplete，不能宣称样本验收完成，也不会为此覆盖撤回状态。资源检查仅请求本机API和本机封面，不访问OSS。接口自动测试不等于浏览器验收。

## 4. 内容维护与撤回

本轮3篇全文JSON样本位于`content/reading/`（旧guide文件不进入镜像或发布包），维护入口只有容器CLI，公共API只读。新全文稿必须核对许可、原始语言、完整性、用途与署名，并属于人工配置的government_candidate来源；不能仅凭NASA域名自动授权。全文须用complete_checked。旧guide结构仅为历史兼容保留，不公开展示或在批量部署中导入。未知HTML字段、嵌入脚本、图像、翻译/AI许可启用及超限稿件均拒绝导入。

```bash
# 新版经核对后显式导入；不自动抓取任何URL
docker compose exec -T app python -m tools.reading_manage import /app/content/reading/稿件.json
# article_id从/api/news获取；撤下正文及审核正文预览
docker compose exec -T app python -m tools.reading_manage withdraw 文章ID --reviewer '维护人' --reason '撤回原因'
# 撤回后重新发布需要显式参数，不能由重跑部署自动恢复
docker compose exec -T app python -m tools.reading_manage import /app/content/reading/稿件.json --republish
```

服务器每次请求重新核对许可，三种新闻接口都no-store。正文/许可状态变化更新content_version，旧段落定位须使用(article_id,content_version,block_id)。打开的弹窗30秒复查一次，回到标签页时再读取；无法确认时隐藏正文。已被用户复制或下载的内容无法从其设备追回。后续图片上线须有独立许可与可撤回的访问控制，本轮不提供图片URL。

## 5. 回滚

自动失败恢复原镜像并保留当前数据库：新增表是附加迁移，旧版读新闻不需要删表。旧版没有阅读接口或许可过滤，不应继续对外提供本轮的阅读功能。

若需要代码回退，使用本次`/root/space-news-before-reading-时间.tar.gz`恢复代码，并把证据中的previous-image-id.txt镜像重新标记为Compose当前镜像后重建。不要`docker compose down -v`，不要覆盖.env，不要删除数据卷。

数据库恢复应先停止app，把`before.sqlite3`复制成一个新命名卷中的`news.sqlite3`，所有者10001:10001，再在隔离服务验证数量、身份和队列；核对后再切换应用卷。恢复期间暂停新采集，当前卷保留以防丢失备份后新增的记录。不要在运行中的数据库上覆盖文件或只复制主库而忽略WAL。
