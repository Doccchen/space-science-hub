服务器 SDK 和 HTTPS 探针通过：协议 `2025-06-18`，发现 `read_news`；文章 362 完整返回 33 个正文块；跨文章和无上下文调用被拒绝，未授权 HTTP 请求返回 401。百炼控制台实际工具测试也完整读到文章 362，跨文章 363 返回 `blocked/tool_scope`。有效上下文最多 3 次读取，测试令牌 15 分钟过期。

应用版本 2（19:40:48）关联 MCP 后，使用新的独立任务，通过 `input.biz_params.user_defined_params.<服务ID>.X-News-Context` 发起一次应用调用；控制台仍保留旧的已过期测试令牌，用于区分动态覆盖是否发生。回答明确工具被拒绝；新任务 `tool_calls=0`、`full_read_verified=false`，用量 3,724 tokens。**模型返回完整答案不代表原文读取成功。** 此映射未在 Agent 2.0 本应用通过，未设置 verified。

文档存在版本差异：新版 API 示例给出自定义插件参数传递，而 Salesforce MCP 文档明确该 Access Token 透传仅适用于 Agent 1.0。因此不能把通用插件参数示例推广为任意 Agent 2.0 自定义 MCP Header 均可传递。当前证据只证明本次方式失败，不断言新版所有可能方式均不支持。

用户选择保留 Agent 2.0 后，应用版本 3（19:50:11）解除 `read_news` 关联，云端 MCP 测试连接暂停，服务记录保留；原提示词、模型、知识检索服务和来源展示设置保留。服务器 MCP 仍执行原有严格范围检查，没有改成静态密钥加模型 article_id 的宽授权方式。

## 复现与回退

服务器只读配置检查：

```sh
docker exec space-news-app-1 python -m tools.probe_news_agent_inline
```

需要新的有预算私有验收时显式使用 `--call --follow-up`，最多两次，失败不自动重试；不要把这个命令当作周期任务。MCP 动态上下文未解决前不得将 `NEWS_MCP_CONTEXT_VERIFIED` 设为 1。

正式发布使用 `tools/package_news_agent.py` 生成固定文件包，经 SHA256 核对后在服务器运行 `tools/deploy_news_agent.py`；会备份配置、在线 SQLite 数据、保留镜像快照，隔离检查通过才重建 app，失败自动恢复。

本轮修正回退：在 `/opt/space-news` 将 `space-news-agent-before:20261008T115523Z` 重新标记为 `space-news-app`，恢复该证据目录中 `.env` / Compose 备份，然后仅重建 app。不要恢复旧 `news.sqlite3` 覆盖期间新增新闻；新增独立表/加密凭据保留。要撤回整个新闻后端部署时使用初次部署前快照，并恢复初次备份配置；HTTPS 单独保留。百炼版本 1 可作应用配置回退参考，版本 2 仍带未通过动态透传的工具关联，不宜恢复为公开运行配置。
