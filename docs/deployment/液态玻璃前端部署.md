## 服务器执行

```bash
cd /opt/space-news
bash -n /root/upgrade_glass.sh && bash /root/upgrade_glass.sh
```

脚本先检查当前容器与页码 API，再校验压缩包成员及 SHA256。宿主机 web 和运行容器 web 分别备份到 `glass-upgrade-UTC时间`，保存原镜像 ID 与卷名。更新宿主机四个文件并构建 app 镜像，使将来容器重建仍有新版前端，然后热更新当前 app 容器四个文件（index 最后写入），不用重启采集。镜像构建可能需要服务器访问现有镜像源/依赖源；已有缓存通常可复用，以实际构建结果为准。

随后检查实际 HTTP 静态文件、运行容器 SHA256、健康/新闻/资料 API，并确认容器 ID 未改变。失败自动尝试恢复原 web 文件与原镜像标签，保留日志。新主题文件在回退后可能仍存在，但原 index 不引用它们；不删除未知文件。不修改 `.env`、Compose、数据库、持久卷、后台或 OSS 权限。

完成标志：`Glass frontend upgrade passed`。这表示服务器静态文件及 API 检查通过，不替代用户浏览器验收。浏览器 Ctrl+F5，检查四类别、来源/商业地区、10/20/50 条、翻页/跳转、正文弹窗、资料搜索和下载、减少透明。手机主分页显示上一页/当前页/下一页。

如果前置检查提示 `Deploy the numbered-pagination backend before this frontend release`，先按已有《新闻页码分页部署》更新后端，再运行本脚本。不要将前端更新包视作后端分页包。

发生失败时提供末尾输出与 `glass-upgrade-*` 目录位置；不要发送 `.env`、私钥或备份内容。Git 提交与推送不是本次部署的必要条件。
