## 生成独立主密钥

第一次生成时使用新的密钥路径，已有密钥切勿覆盖或重新生成：

```bash
install -d -m 700 -o 10001 -g 10001 /opt/space-news/secrets
docker run --rm --user 10001:10001 --mount type=bind,src=/opt/space-news/secrets,dst=/secrets space-news-app python tools/ai_manage.py generate-key --output /secrets/site-management.key
```

工具排他创建 0600 文件，不输出密钥。容器运行 UID/GID 10001；主密钥在宿主机独立目录，不放进 `/data` 管理库或镜像。密钥必须在独立、受保护位置单独备份，恢复加密配置同时需要该密钥与管理库。不要贴出、录屏或打印文件内容。

## 合并 Compose

保持原 `.env`、公开端口、共享命名卷和 SSH 后台访问方式。两个服务都保持 `image: space-news-app` 和 `MANAGEMENT_DB_PATH: /data/site-management.sqlite3`。

app/admin 各自的 environment 增加：

```yaml
      AI_MASTER_KEY_FILE: /run/secrets/site-management.key
```

admin 的 environment 另增加（app 已有）：

```yaml
      AI_DB_PATH: /data/ai.sqlite3
```

两个服务的 volumes 均为：

```yaml
    volumes:
      - news-data:/data
      - ./secrets/site-management.key:/run/secrets/site-management.key:ro
```

先生成文件再加挂载及重建，防止缺失宿主文件被误建为目录。业务 Key 仍由 app 的原环境提供，用于下一步显式采纳；无需将 DASHSCOPE_API_KEY 复制给 admin。`review` profile 名保留以兼容原命令，但服务已不挂载新闻审核接口、不运行审核线程。

## 离线验证、停服备份、启动

新镜像离线验证不挂载生产库或密钥，仅挂载测试源码：

```bash
docker run --rm --mount type=bind,src=/opt/space-news/tests,dst=/app/tests,readonly space-news-app python -m unittest discover -s tests -p test_ai_management.py -v
docker compose config --quiet
docker compose --profile review stop app admin
mkdir "$backup/data"
docker cp "$old_app:/data/." "$backup/data/"
docker compose --profile review up -d --no-build --force-recreate app admin
docker compose --profile review ps
```

停止两个容器后复制完整 `/data` 快照，包括 SQLite 主库/WAL/SHM、图片及资料启用标记；此时没有活动写入者。备份不在命名卷内，也不复制密钥进入同一目录。保留原卷，不执行 `down -v`。这段会有短暂服务不可用。

测试只用临时库与假 Key，不调用百炼；在服务器真实 Linux 镜像尚未执行前不能称之为服务器验收。等待 app/admin healthy 后显式初始化：

```bash
docker compose exec app python tools/ai_manage.py init
docker compose exec app python tools/ai_manage.py inspect
```

首次 init 从 app 现有环境采纳开关、连接与额度，加密保存并创建 `/data/site-management.ai-enabled` 标记。重复 init 不覆盖已保存配置。后台配置及“停用”优先于旧环境；主密钥或已启用的管理库丢失，重启不能退回环境再次启用。首次正常初始化保持原会话兼容版本；后续连接或启停变更更新兼容版本。

正常约 2 秒内同步，inspect 应显示 `status=applied`、目标/加载版本一致、心跳新鲜。inspect 的字段不含业务 Key 或主密钥；不要运行 `docker compose config`（无 --quiet）或打印完整环境来检查密钥。

## 页面验收

仍通过 SSH 转发打开 `http://127.0.0.1:18080`。登录后只有“资料管理”“AI 设置”，原管理员账号继续有效。

- 先核对 28 份资料及已有下载/历史；不要重新导入旧目录覆盖修改。
- AI 页面仅显示 Key 已配置/未配置，替换输入框空白。留空保持当前草稿密钥，保存草稿不改变访客配置。
- 用“停用→保存草稿→应用”检查状态及前台提示，再启用应用。均不会自动调用百炼；当天次数、Token 和在途预留不重置。
- 数值变更保留旧会话；连接变更、启停和回退使旧会话需要重新开始。已开始的回答按原配置完成，用户删除/过期保护继续有效。
- “恢复上一生效版本”生成新保存版本；有失败或离线时查看脱敏原因及心跳，修复后重新读取。加载成功只证明本站已接受配置，不证明云端认证、知识库发布或问答质量。
- 百炼控制台更改关联知识库/提示词且服务 ID 未变时，勾选“使旧会话失效”后应用；本站无法自动感知控制台内部变更。
- 只有勾选费用确认并点击“测试已保存草稿”才发固定短问题。全站每小时最多 3 次、滚动 24 小时最多 10 次，且同时最多一个后台测试任务。测试由公开进程执行，共用全站预算、并发和用量账本；草稿高额度不能扩大当前可用额度。结果只保留来源数量和用量等脱敏摘要。
- 测试失败、断流或用量未知保留预留，不自动重试或自动替换当前配置；进程重启把旧测试标为中断，不重新收费。

AI 状态同步每秒检查本地配置并上报，后台每 2 秒读取状态。前台每 10 秒读取本站 status（不调用模型），支持启停后的页面状态更新。公网仍不提供任何 AI 设置写接口。

## 后续备份和回退

管理库现在包含加密 AI 历史与资料，沿用 `resources_manage.py backup` 一致性快照。另保管 `site-management.resources-enabled`、`site-management.ai-enabled` 标记；独立主密钥单独备份。完整联合快照需暂停所有写入者；故障恢复不得混用原库 WAL/SHM 与恢复快照。

日常错误优先用后台上一版恢复。回退到旧环境配置驱动的代码前，停止后台写入并导出当前已确认配置：

```bash
docker compose --profile review stop admin
docker compose exec app python tools/ai_manage.py export-env --output /data/backups/ai-current-20261006.env
docker compose exec app python tools/resources_manage.py export --output /data/backups/resources-current-20261006.json
```

两个工具拒绝覆盖已有文件，实际使用新文件名。AI 导出片段含业务 Key，以 0600 创建，不在 stdout 输出。将它通过服务器本机受限工具合并到旧 `.env`（只替换导出的 AI 字段，保留其他环境），不要打印、上传或通过命令参数传递 Key。旧 app 设置 RESOURCES_PATH 指向导出 JSON，同卷重建旧镜像，并停止新后台。单纯恢复原代码/旧 `.env` 会丢失本轮后台参数变化，不能声称无损回退。

保持管理库和独立密钥原样以便重新升级；镜像回退不需要删除任何资料、AI 额度或新闻历史。主密钥轮换不在本轮范围内。
