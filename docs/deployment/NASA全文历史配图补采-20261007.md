## 处理范围

只选择 NASA、未被 APOD 策略排除、当前公开阅读模式为 full_text、且缺少有效缩略图的文章。已有配图及人工撤回图片跳过。每次先固定候选快照，再逐条处理，单篇每次最多尝试一次；明确执行历史补采时可以重新尝试已达三次/仍在冷却期的失败条目。

逐条处理前再次检查当前全文状态、图片状态和撤回状态，避免正在自动采集的文章被无谓覆盖。实际抓取仍调用现有 `news_thumbnails.capture`，保留 URL/robots、署名、许可、格式和大小检查。不会因为正文可以显示就推定所有图片可以使用；无可确认署名/许可的条目返回 unconfirmed，网络问题返回 failed。

成功后图片进入现有 `/data/news-images` 存储与 news_thumbnails 表，网页新闻列表现有配图位置自动显示。本文工具不修改正文发布权限，不回填第三方未经确认的图片，不发送 AI 请求，也不改变自动采集开关。

## 服务器先查看，再补采

先查看全文数量、已有图像、撤回跳过、缺图及所选 ID。该命令不会请求 NASA 或下载图片：

```bash
cd /opt/space-news
docker compose exec -T app python - --max-articles 500 < /root/backfill_nasa_fulltext_images.py
```

执行补采并保存输出：

```bash
cd /opt/space-news
set -o pipefail
docker compose exec -T app python - --apply --max-articles 500 < /root/backfill_nasa_fulltext_images.py | tee "/root/nasa-fulltext-images-$(date -u +%Y%m%dT%H%M%SZ).log"
```

抓取逐篇执行，终端会持续输出结果，旧新闻较多时需等待。`ready` 才表示已经下载保存并可展示；`unconfirmed` 表示暂没有满足许可规则的图片；`failed` 记录具体失败类型；`skipped` 表示状态已变化或图片已存在。结尾的 outcomes 汇总结果，deferred 表示超出本次上限的候选。

刷新网页后检查新图像与署名。对失败条目可以沿用 inspect/retry 命令进一步定位，不能把候选解析成功或全文已发布当作图片已成功保存。
