## 2. 服务器备份、解压与升级（Linux）

登录现有服务器后复制执行整个代码块。若上传未完成或文件不存在，命令会停止。不要改动已有.env中的监听、镜像和包索引配置。

```bash
set -e
test -f /root/space-resources-release.tar.gz
test -d /opt/space-news
stamp=$(date -u +%Y%m%dT%H%M%SZ)
tar -czf "/root/space-news-before-resources-$stamp.tar.gz" -C /opt space-news
tar -xzf /root/space-resources-release.tar.gz -C /opt/space-news
cd /opt/space-news
bash -n tools/upgrade_resources.sh
bash tools/upgrade_resources.sh
```

脚本保留.env和原news-data卷，保存一致性数据库备份、全部旧新闻身份、历史回填任务与队列、来源启用标记、旧镜像与调度状态。构建升级后先禁用采集进行隔离检查，再恢复原调度状态；不启用新来源、不做历史回填，不执行down -v。

构建前失败时旧容器保持运行；替换容器后检查失败会尝试恢复原镜像，保留当前数据库，不自动用旧备份覆盖数据。全过程证据保存在/opt/space-news/resources-upgrade-UTC时间目录。
