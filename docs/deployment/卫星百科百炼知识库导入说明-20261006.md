| 文件 | 用途 |

每篇文档开头即为词条名与正文，详细来源、修订链接、作者历史和许可位于末尾，避免元信息占据首段正文检索空间。原站“航天员”的需要更新、“火箭发动机”的正在施工提示保留在相应文档中。

## 格式核对依据

阿里云官方文档列出 `.md`、`.txt`、`.html` 为支持的纯文本格式，建议单文件在 10 MB 以内；单次上传最多 50 个。Markdown 可按标题切分。本批 30 个 MD，最大文件约 35.5 KB，满足上述格式及数量条件。[文档管理与解析](https://help.aliyun.com/zh/model-studio/rag/documents) · [容量与限制](https://help.aliyun.com/zh/model-studio/rag-knowledge-base-specifications)

文件数据集用于非结构化文档；当前新版界面也可能通过文件连接器管理类目。根据所用控制台选择相应文件入口，不选表格数据集，不把本地 JSON 清单当作正文导入。[数据集](https://help.aliyun.com/zh/model-studio/data-connection) · [文件连接器](https://help.aliyun.com/zh/model-studio/connector/file)

以上为公开文档核对，尚未在用户业务空间实测导入；最终成功需以控制台解析完成及切片检查为准。账户、区域、权限与界面可影响具体入口。[Agent Studio 知识库](https://docs.agent.bailian.aliyun.com/zh/flow-agent/knowledge-base/create-and-use)

## 导入步骤

1. 进入当前网站使用的北京业务空间，找到文件数据集（或文件连接器）及知识管理入口。新建独立类目，如 `卫星百科-20261006`，避免覆盖已有 PDF 资料。
2. 解压 ZIP，只选择 `上传文件/` 中的 30 个 `.md`。文件名包含来源和词条名，便于网页展示检索来源以及后续版本替换。
3. 在目标文档搜索知识库选择这些文件；如果仅上传到了数据集而未加入知识库，尚不能据此认为 AI 已可检索它们。
4. 解析使用文本方案即可。切片先使用平台智能切分或按标题切分，段长先保持界面默认值，再根据预览调整；本包没有预先限制每个切片的 token 数，也不能保证所有公式和表格自动保持完整。
5. 界面支持时，将文件名作为元信息附加到切片；来源名称可设为“卫星百科”。文档内的出处是可解析正文，不依赖 YAML 前置元数据或 JSON sidecar 自动识别。
6. 等待各文件解析完成，查看切片，确认正文、公式及参数记录进入索引。文件上传完成不等于索引完成。
7. 让网站使用的已发布知识问答服务关联该知识库；沿用原业务空间、API Key 与服务 ID时，不需要更改网站配置。若新建服务，则按原百炼部署文档更新服务标识。

切片推荐为本项目建议，非平台固定要求。不要因追求切片更小而切断公式及其变量说明；长公式保留的是原始 TeX 文本，不承诺平台预览会排版成数学图形。Markdown 表格另附逐行“字段：值”记录，用于减轻拆片后的字段含义丢失。

## 上传后的检查

先做控制台文本解析与命中预览，检查以下资料：

| 词条 | 检查点 |
|---|---|
| 航天 | 标题、定义和中文字符完整；没有站内导航和 Wiki 模板残留 |
| 第一宇宙速度 | 公式和变量说明都在，TeX 中的括号、上下标和反斜线未丢失 |
| 太阳同步轨道 | 进动公式完整，参数表的列名、单位和数值对应 |
| 两行根数 | 第一行和第二行字段区别明确，列号如 `03-07` 未被改成日期 |
| 液体火箭发动机 | 章节和原参考资料保留，没有把图像文件名当成正文 |
| 航天员、火箭发动机 | 原站需要更新/施工标记未删除 |

首批资料只是历史快照，涉及“目前”“预计”“截至”等表述时应参照版本时间。`两行根数`原表有重复的“08”行，本包按原样保留，不声称已纠正原站事实问题。格式和信息保留校验不等于科学事实审核。

如需检索或问答验证，可分别使用“低地球轨道是什么”“TLE第一行BSTAR在哪些列”“太阳同步轨道进动公式中各变量是什么”。这些是验证问题，不在本包中添加模型生成答案。预览与检索也可能涉及向量或模型用量，以账户计费为准；本轮没有执行云端验证。

## 可重复整理

在项目虚拟环境安装准备工具依赖（不加入网站生产运行依赖）：

```powershell
.\.venv\Scripts\python.exe -m pip install -r tools\requirements-satwiki.txt
.\.venv\Scripts\python.exe tools\prepare_satwiki_bailian.py --output artifacts\satwiki-bailian\<新的批次目录>
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_satwiki_conversion.py -v
```

转换入口要求输出目录为空，核对原始 XML和 Wikitext 校验值，仅处理首批 30 篇正文；模板、模块和版权页面保留于原始档案，不作为独立科普文件上传。今后扩展名单、正文模板或命名方式，需要相应调整并重新检查，不能把本工具视为适用于全站任意词条的通用渲染器。
