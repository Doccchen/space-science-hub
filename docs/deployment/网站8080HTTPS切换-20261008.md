## 当前入口与网络

- 网站：**https://8.137.164.100:8080/**。
- 旧 `http://8.137.164.100:8080/` 返回 **308**，跳转到同 IP、同端口的 HTTPS 地址，保留请求路径。
- Nginx 在公网 8080 终止 TLS；应用容器只发布 **127.0.0.1:18081 → 8000**。没有新增公网明文后端入口。
- 443 仍为仅 MCP 的网关，其 upstream 已同步改为 18081。新闻 MCP 后端尚未部署，当前 MCP 路径仍返回 404。
- 80 继续仅提供 ACME challenge 文件；管理后台仍为回环地址 8090，没有通过新网站代理公开。
- 沿用前轮正式 IP 证书及续期定时器；续期重载 Nginx 同时覆盖 443 与 8080。

## 保留线上页面与数据

初次 `docker commit` 因服务器原镜像 content digest 缺失而失败，失败发生在入口修改之前，原应用仍运行、未 paused。改用运行容器文件系统 export/import 重建快照，恢复 User、WorkingDir、Entrypoint/Cmd 与 Python 基础环境；没有把模型 Key 加入新镜像元数据。运行配置和密钥仍由已有受保护配置/持久卷提供。

使用 SQLite online backup 创建 9 份一致性数据库副本，仍挂载原有命名数据卷。切换后新闻总数为 **363**。只重建 app，未重建 admin，也没有升级功能代码或执行收费模型调用。

## HTTPS 来源校验与会话配置

- Nginx `Host $http_host` 保留请求端口，转发 `X-Forwarded-Proto $scheme`；覆盖 X-Forwarded-For 为实际客户端地址。
- 新 `/opt/space-news/compose.override.yaml` 将 app 的 `FORWARDED_ALLOW_IPS` 限制为 `127.0.0.1,172.18.0.1`，后者是实测 Docker 网关；没有使用通配信任。
- `.env` 仅更新绑定地址、端口及 `AI_COOKIE_SECURE=1`，保留其余字段，文件权限为 600。Nginx 也为 AI/news visitor Cookie 设置 Secure、HttpOnly、SameSite=strict。
- AI 服务在切换前已关闭，切换后状态完全一致。正确 HTTPS Origin 的创建请求到达服务并返回 disabled 503，错误 Origin 返回 403。没有为 Cookie 测试临时启用模型服务，也没有创建实际 AI 会话或发送问题；启用服务后仍应补充真实 Set-Cookie 与会话删除验收。

未来升级应用可继续使用默认 `docker compose`（自动加载该 override），但必须保留私有绑定和可信代理设置。若重建 Docker 网络导致网关变化，需重新核对该字段，不能直接改成 `*`。
