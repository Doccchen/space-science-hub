## 验证目标

先验证 1 次你确认知识库能够回答的问题：发布服务可调用、SSE 完整结束、回答及检索来源形态、用量与耗时。协议基于[百炼官方知识问答 API](https://help.aliyun.com/zh/model-studio/knowledgechat)：workspace 网关、`agent_options.agent_id`、`stream=true`、生成阶段与 `generation_end`。实际响应是后续适配的依据。

默认业务空间 `llm-ep9bqc9mnw50k8e0`，服务 `aid-066ddd0b6e1e44d6bf7d620e0ac7c060`，北京知识问答网关。执行前在控制台核对 API 示例与服务已发布状态。如果控制台地址/服务类型不同，先停止并核对，不盲目试多个接口。

首轮只调用 1 次。脚本还准备 4 用例序列：可答、换一种表达、引用第一题历史追问、虚构型号资料不足。首轮确认后可选执行 4 题；该步骤会再次调用第一题，因此两次运行合计最多 5 次，不自动重试或自动运行第二轮。没有评估账户具体模型价格，不能预估费用为固定金额。

## 2. 服务器首轮执行

```bash
bash -n /root/run_bailian_probe.sh && bash /root/run_bailian_probe.sh 1
```

首次输入一个已在百炼控制台证实可答、适合测试的问题。可以使用公开的学习问题，不填个人信息或业务秘密；问题被发送给已配置百炼服务。随后隐藏输入 API Key，不显示字符，不写到 shell 历史或文件。若终端没有输入提示，不要把密钥当作下一条命令粘贴。脚本从环境读取已有 Key 时不再提示；不会读取网站 `.env`。

如果服务标识确需覆盖，执行前设置 `BAILIAN_WORKSPACE_ID` 和 `BAILIAN_AGENT_ID`，不要设置任意外部 URL。密钥应与已核对的服务权限匹配。

脚本利用当前 app 容器现有 Python/httpx，在 `/tmp/bailian-probe-*` 执行独立 CLI，无监听端口；临时以容器 root 用户运行仅为读取 docker cp 的私有文件。既有网站进程仍以原用户运行。不会安装依赖、重建镜像、重启容器、启用网站 AI、修改应用/知识库/数据库或导入新闻。

60 秒总超时、15 秒读取等待、10 秒连接超时；最多 4 MB 流与 10 万字符答案，顺序调用。任何 HTTP/业务/格式/超时/断流错误停止后续请求；未知超时仍可能已计费。不会在缺引用或答案不理想时自动追加请求。

## 3. 结果与发回内容

结果复制至服务器 `/root/bailian-probe-work/results-UTC时间-进程号/`，目录 700、文件 600。终端自动显示 `summary.json`，可以将这个 JSON 发回。它不含问题、答案、检索正文或文件 URL。

`supported-private.json` 等详细文件仅留服务器，由你人工查看：问题、生成阶段分片/拼接答案、无思考文本的事件结构、工具调用/返回、检索 docs、原用量帧。URL 与密钥字段已隐藏，但文件名、内部 ID、知识库文字及回答仍可能含业务内容，不能把详细文件视作可随意公开的完全脱敏文件。普通退出不会自动清除结果，便于核对；保留期限由你决定。

摘要字段：

- `transport_complete`：观察到生成结束、stop，无后续错误且有回答；不是答案正确或引用有效的判定。
- `http_status`：接口 HTTP 状态；HTTP 200 仍可能有流内错误。
- `doc_count`、`doc_field_sets`、`tool_names`：本次来源记录数量和结构，不证明绑定了指定知识库。
- `final_usage`：生成结束帧的用量，未将中间计数相加；null 表示无法确认最终用量，不表示免费或零用量。
- `simple_bracket_candidates`：仅 `[1]` 这类语法候选。实际协议可能使用其他引用形式，必须人工查看详细回答；普通数字括号也可能不是引用。
- `request_ids`、`elapsed_seconds`：用于平台定位和延迟评估。

请人工核对：答案是否与控制台相符；检索工具参数和来源是否属于你的目标知识库；答案是否增量片段还是累计快照（详细文件保留生成分片）；引用编号实际语法；关键结论是否由对应片段支持。脚本不把无来源回答自动判为拒答，也不宣称带来源就一定正确。

## 4. 首轮确认后可选的四题验证

待首轮问题定位完毕，再手动执行：

```bash
bash /root/run_bailian_probe.sh 4
```

使用现有问题文件，历史只给追问题传入第一题的 user/assistant，其他题独立。不按经典应用 session_id 机制调用。最后一题的虚构型号用于观察是否编造参数，但一条缺失用例不证明系统已能稳定拒答；后续网站实施仍需更大人工评测。
