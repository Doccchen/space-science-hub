## 回退根因

`/opt/space-news/unified-upgrade-20261007T132620Z/run.log` 显示新镜像构建完成后，脚本停止写入服务，试图用旧镜像 ID `sha256:f22b06106c369f957bdb711b808011440ead2c83a0e9fce632c560150653b750` 启动数据备份助手。Docker返回 No such image，退出125。回退恢复旧源码，但旧镜像重新打标签也失败；没有 DEPLOYMENT_OK 或 deployed-revision.txt 成功记录。

之后出现 `/opt/space-news/nasa-credit-upgrade-20261007T143025Z`。该脚本仅替换配图模块，再从现有源文件构建；源文件既已回退，重新构建便重新带入了旧前端。这是脚本回退流程的问题，不是用户选择取消设计，也没有证据表明 GitHub 代码丢失。

## 本地修复

- 在任何源码替换和重建前，将实际运行容器固化成单独的本机回退镜像标签；不再仅记录可能无法继续引用的旧镜像 ID。
- 固化时清空镜像元数据中的 DASHSCOPE_API_KEY；原 `.env` 仍不读取或替换。挂载的数据与密钥不会由 docker commit 保存，仍使用原独立数据快照流程。依据 [Docker 官方说明](https://docs.docker.com/reference/cli/docker/container/commit/)。
- 数据备份助手使用刚刚构建且可运行的应用镜像，挂载旧容器的数据卷，只执行标准库备份，不依赖已不可用的旧镜像。
- NASA 小补丁的回退镜像也同样提前固化。新升级继续保留现有配图、数据库、密钥和运行开关，最终检查知航名称和全部资源哈希。

旧镜像不可用场景已用实际备份命令和模拟 Docker 复现（修复前退出125），修复后应通过。未以此模拟测试宣称服务器已恢复；用户仍需重新上传完整升级包和对应脚本后执行。

再次部署用[整站统一升级](../deployment/整站统一升级-20261007.md)。必须将新包、SHA256、revision与脚本四文件一起上传，不能只重跑已经回退过的旧脚本。新包同时含NASA署名修复，因此不会为恢复前端而丢失新增配图规则。
