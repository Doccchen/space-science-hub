# 资料管理后台实施记录

日期：2026-10-06。范围：实施方案阶段 1 的资料基础及阶段 2 的资料管理。未开发 AI 配置后台，未连接服务器、执行生产迁移、部署或收费调用。

后续服务器反馈：用户提供 app/admin 均 healthy、首次迁移 28→28、ID/路径一致、active=true 的输出，并确认“测试正常”。资料管理已完成用户侧部署与页面测试；这是用户反馈和日志证据，不是 Agent 远程独立验收。AI 后台后续准备见对应新记录。

## 已实现

- 独立 `site-management.sqlite3`，含目录、不可变历史修订、脱敏字段变更审计、数据库版本、迁移状态和持久化文件检查频率记录。
- `resources_manage.py` 显式迁移，源目录完整校验后事务导入；重复迁移只对比、不会覆盖后台修改。保留现有 ID、路径、排序、上下架状态及元信息。
- 前台资料列表、详情、下载入口从启用的共享管理库读取，无目录内存缓存；沿用 API 格式和 302 下载模式，增加 no-store。启用标记独立于数据库，丢库/坏库时返回 503，不复活旧 JSON，新闻仍可运行。
- 只在私有 admin 服务挂载列表/详情、新增、修改、历史、恢复和文件检查接口；复用原身份、Origin/CSRF 校验。乐观修订及唯一文件路径冲突不覆盖目录；资料写入、历史和审计在一个事务完成。
- 新增默认下架，已有资料 ID 不变。封面可为空或选已有本地 JPEG，后台鉴权封面路由遵循现有 `img-src 'self'` CSP；不新增文件上传。
- PDF 输入仅接受固定 OSS 来源的完整无参数 HTTPS 地址或原始 public/ 对象路径；URL 严格单次 UTF-8 解码，路径、控制字符及 PDF 扩展校验。中文、空格、文字中的 `%` 正确编码。
- 手动 HEAD 检查限时、限频，不跟随重定向、不读取 PDF；不自动更新文件大小，明确由管理员填入并再次保存。
- 后台新增资料导航、搜索、状态筛选、表单、变更摘要、二次保存、重新加载和历史恢复；未保存修改离开提示，保存冲突保留输入。
- SQLite backup API 一致性备份和旧 JSON 导出；已写明标记恢复、同数据卷、UID/GID 10001 及旧镜像目录读取安排。Compose app/admin 共用显式镜像名，并配置同一管理库路径。

## 页面设计与检查

采用 Extension 模式：沿用原后台浅色背景、深蓝操作色、Microsoft YaHei、1050px 容器、细边框及 4–7px 圆角，不新增动画。设计取值：视觉变化 2、动画 1、信息密度 7、素材依赖 2、现有样式保真 10。桌面表单双列，小屏改单列；按钮及输入有焦点、禁用反馈，列表提供加载及空状态，动态文字使用 textContent。保留新闻审核表单、路由与业务契约。

资料脚本先注册 session 监听，再启动原后台鉴权脚本，避免首次登录事件丢失。代码检查核对表单 ID、脚本路径、私有封面路由及无 innerHTML。没有执行真实浏览器视觉验收；服务器用户仍需按部署说明验收展示和操作。
