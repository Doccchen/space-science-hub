# 论文查找助手改造记录 · 2026-10-19

## 用户确定的范围
在 GPT-WebSite 原目录改造现有阅读助手，不另建整合项目。沿用知航米白/深蓝/橙色风格，公开入口由上传阅读改为论文查找。不建设个人论文库或笔记，不部署服务器。

## 已实施
- 保留 `/reader/` 地址，网站导航、首页入口改为“论文查找”。
- 新闻详情新增“查找相关论文”，以新闻 ID 跳转；新页面从同源新闻接口带入标题及当前可展示正文，不把正文塞入 URL，不自动发送到模型。
- 输入新闻或技术名称，百炼提取最多四个技术主题及英文检索词；用户确认、切换或编辑后检索。缺少模型、模型返回异常或达到调用上限时回退关键词识别。仅有型号时不凭空补出技术。
- Crossref / Semantic Scholar / NASA NTRS / arXiv 并行检索，每个来源最多 12 条，DOI 和保守标题匹配去重，保存来源归属。
- 排序依据标题/摘要的关键词匹配，显示关联理由；首屏八条，可展开更多，支持年份、类型、公开全文入口筛选。
- 题录、作者、年份、摘要、链接只取来源返回记录；不由模型编写论文。不把缺少摘要或全文描述为已阅读。原始摘要可展开。
- 来源错误、限流、无记录和全部失败分别提示；不静默伪造结果或重试付费模型。检索记录只在浏览器当前页面，来源题录缓存于进程内十分钟（最多二百组），不建立个人记录。
- 模型提取最多三十秒，来源请求最多十八秒，站点同时处理三个操作，每分钟最多三十个请求；AI 调用按 READER_SITE_DAILY_CALLS 限额（当前进程滚动二十四小时，重启重置）。
- 公开服务入口 reader/app.py 不再启用 PDF 上传、解析和问答。旧实现保留 reader/legacy_app.py，旧阅读测试改为针对该保留模块。新服务与 Docker 不再依赖 PyMuPDF；独立原阅读项目未修改。

## 设计记录
Redesign · Preserve。面向从新闻寻找技术资料的访客，保留实际 `web/brand.svg` 标志；纸色 #f3f1ea、正文 #10233f、强调 #a33d18，宋体标题与微软雅黑正文，细边框、5px 圆角。布局为新闻输入、主题确认、文献列表，移动端纵向排列。设计变化 3/10、动效 1/10、信息密度 6/10、素材依赖 2/10、品牌保持 9/10。沿用用户此前确认的风格与本次批准的流程，无新增视觉方向确认。

## 本地预览
项目目录运行 `./start-integrated.ps1`，打开 http://127.0.0.1:8878/reader/ 。已运行的旧服务需先在其原终端 Ctrl+C 后重启。主站采集仍由预览脚本关闭。保留 --reader-python 可选参数，但新服务无需 PDF 专用环境。

## 验证与边界
- 十项模拟后端/网关测试通过：四来源格式、DOI去重、冲突DOI隔离、缓存、限流与坏格式、全部失败、输入与来源校验、模型失败回退、未提及技术过滤、模型额度回退、新闻入口。
- JavaScript 语法检查通过；论文查找页交互测试通过（技术切换、结果显示、危险链接过滤、筛选、过期结果清除、网络失败恢复）；现有书架与新闻前端回归检查通过。
- 已沿用现有百炼配置实测技术提取。发现模型会推断未提及应用场景后，增加了技术名必须逐字来自输入的校验，并对已知技术采用受控英文检索词；复测返回“绳网回收技术 / tether net capture dynamics”。
- 真实通用检索词 `tether net capture dynamics` 返回 Crossref 12 条、NASA NTRS 1 条、arXiv 5 条，去重后 16 条；Semantic Scholar 返回 HTTP 429，已按部分失败处理。
- 不少绳网论文研究空间碎片捕获。只表示可参考的技术研究，不代表火箭采用了相同方案。当前没有对论文具体结论作全文核验。
- 中文数据库提供原站检索跳转，未接入授权题录接口；公开全文入口仅在来源提供时显示，不保证可下载。
- 当前用户未要求浏览器验收，未执行浏览器或跨尺寸实机验收。
