# 航天新闻抓取与展示：首版实施方案

日期：2026-10-05。优先级：新闻与科普 Agent 优先，资料下载后置。本文件仅规划新闻首版，没有创建生产采集服务。

## 实测与来源范围

本机只读访问官方 RSS，NASA 新闻 feed 返回 HTTP 200、解析出10条，ESA feed 返回 HTTP 200、解析出9条。此结果只证明本次本机网络可访问，不代表阿里云服务器出网已验证。

- NASA：https://www.nasa.gov/news-release/feed/ 。入口见官方 https://www.nasa.gov/rss-feeds/ 。具体条目是否为新闻稿应以返回链接和内容类型核对，不能只按feed名称判定。
- ESA：https://www.esa.int/rssfeed/Our_Activities/Space_News 。入口见官方 https://www.esa.int/Services/RSS_Feeds 。
- 中文源候选：国家航天局 https://www.cnsa.gov.cn/ 。在服务器验证列表、详情解析和允许使用方式后接入；失效时采用管理员手动录入来源链接及必要的摘要，明确人工录入，不冒充自动抓取。

首版优先NASA、ESA，再增加一个中文官方源。不引入SNAPI、RSSHub、公众号、商业公司和专业媒体的全量接入。后续有明确需求再添加。

## 新闻闭环

采集任务获取RSS/指定列表 → 解析 → 校验来源和链接 → 标准化字段 → 幂等入库 → FastAPI查询 → 现有简洁前端展示。

页面只从自己的后端读取已入库新闻，不让每个访客触发上游抓取。不需要大模型参与新闻入库；英文标题与摘要首版保留原文，自动翻译属于后续功能，必须明确标注。

## 首版页面

采用文字优先的行式列表。每条显示标题、来源、发布时间、简短摘要、原文链接。提供全部/NASA/ESA/中文来源筛选及“加载更多”，首批20条。列表标示本站最近成功更新时间；来源失败仍保留已入库内容，不能将旧数据标成实时更新。

首版无图也应完整可用。图片可以后加，不以绕过防盗链或搭建任意图片代理作为前置需求。原标题与来源摘要保持原始语义，不自动补写缺失参数。

新闻详情页显示相同字段、来源链接及材料可用范围，为后续Agent留位置。真实Agent接入前不提供一个伪生成按钮，不跳转到不相关的固定示例。

## 数据结构

sources：id、name、feed_url、publisher_allowed_hosts、source_type、enabled、last_attempt_at、last_success_at、last_error、etag、last_modified。

articles：id、source_id、source_item_id、original_url、canonical_url、title、source_summary、published_at（可空）、date_status、first_seen_at、last_seen_at、content_hash、lang、optional_image_url、material_status。

时间存UTC、前端按用户时区展示，发布时间缺失明确写“未提供”，不能使用采集时间替代。

首次运行保留feed现有记录，之后按来源条目ID/规范化URL更新。仅删除明确的跟踪参数；保留业务参数和路径大小写；不强制转换http到https。同一事件不同来源保留独立新闻，不做事件聚合。

## API

- GET /api/news?source_id=...&cursor=...&limit=20：按发布时间倒序、缺失日期后置，使用id作为稳定排序的第二键；游标编码排序信息。
- GET /api/news/{id}：元数据、摘要、来源地址、material_status。
- GET /api/news/sources：来源、启用状态和成功更新时间。

限制limit最大值；首版没有对外可触发的采集接口。需要管理员更新时采用受保护的命令或接口。

## 采集实现

Python + httpx + feedparser，单个定时任务每60分钟运行一次，启动时抓取一轮。中文HTML源按需要增加BeautifulSoup。

请求超时约15秒、并发最多2个源、短暂故障最多重试2次并退避。支持上游提供的ETag/Last-Modified、遵守429与Retry-After；限制响应体大小，单源失败隔离。解析后的标题和摘要输出为文本，不能直接把不受信任的RSS HTML插入网页。

校验来源对应的文章域名；重定向需重新检查地址，拒绝本机/内网地址。提取配置发生变化时记录失败，不根据缺字段生成虚假内容。

调度只启动一次，使用任务锁避免重叠；独立采集入口或单进程调度均可，不随多个Web worker重复创建。SQLite用短事务、唯一约束及busy timeout，配置持久卷与一致性备份。

## 与科普Agent衔接

material_status区分summary_only与evidence_ready。

只有RSS摘要的新闻，只允许基于这份摘要解释，不能声称引用完整原文。若需要专业摘要/科普双版本，在允许条件下收集正文并保存分段证据、来源位置、获取时间和版本；无法获取时让用户提供有权使用的材料。正文证据存储与对外全文转载是两件事，分别按来源规则处理。

2026-10-05连接检查：本机能与8.137.164.100:22建立TCP连接，但服务器在SSH版本交换/握手阶段关闭连接，尚未进入密钥验证。当前没有成功登录或安装/修改服务器服务，不能据此判断密钥有效性。用户已确认本机终端使用相同密钥、root和默认22端口能够登录。Agent执行环境对正确IP的普通与交互式尝试仍在握手阶段被关闭，原因未定，不能归因于密钥错误或服务器配置故障。可由用户在已登录终端执行只读检查并提供结果，再继续准备部署。

部署按Docker Compose组织，Nginx提供前端及/api反向代理，FastAPI单worker运行API，SQLite保存在持久卷。采集调度确保单实例；模型通过外部API访问。容器资源限制和模型请求并发按实测调整，不以2核2G规格承诺支持人数。

下一步使用Ubuntu仓库的docker.io与docker-compose-v2安装Docker和Compose，启动服务，验证镜像仓库及NASA/ESA访问；这一路径使用Ubuntu维护的发行版软件包，不与Docker官方仓库的docker-ce混装。

迁移约定：域名/IP与API密钥放环境配置，前端使用同域相对路径/api，不把8.137.164.100写入业务代码；依赖与镜像版本固定。迁移时复制Compose与配置、使用SQLite一致性备份恢复数据库，并搬迁持久文件；不能只复制容器镜像而遗漏数据。定时采集切换时停用旧实例，防止双端重复运行。若目标环境改为多实例再评估数据库与调度架构。

沿用Nginx + FastAPI + SQLite与Docker，前端使用现有页面骨架。首版不增加浏览器抓取、Redis、向量数据库和RSSHub。采集工作量小，但必须实测服务器的DNS、HTTPS与返回字段，不从本机成功推定线上成功。

在持续投入、服务器/API条件具备的前提下，目标约2—3个工作日：

1. 第一天：阿里云连通验证、两源解析与入库、重复采集校验。
2. 第二天：列表与详情API、来源筛选、现有新闻页接入真实内容、提前部署。
3. 第三天：增加中文源或人工录入兜底、故障与数据持久化验证；并行推进一篇材料的真实Agent闭环。

资料下载功能后置，不影响新闻与Agent交付。

## 完成判据

两次采集不重复入库；至少两个来源有真实记录；原文链接与来源匹配；发布时间/缺失状态可核对；来源失败仍能浏览历史列表；数据库在容器重建后保留；前端筛选与加载更多有效；英文原文不伪装成人工中文译稿；来源更新状态如实显示。
