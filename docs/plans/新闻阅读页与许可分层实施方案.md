最新正文策略（用户2026-10-06再次确认）：政府新闻正文取消逐篇人工审批。NASA、国家航天局、中国载人航天的已登记新闻由主app后台任务自动取回原始正文，通过结构与文本覆盖检查后直接展示；无需管理员登录。其他来源仍原文阅读，图片维持此前独立许可、本机持久保存流程，不随正文自动放行。自动展示是运营方选择，不得生成虚假的版权授权记录；明确撤回、拒绝、已审全文及历史记录保留。本段优先于下文旧人工审批要求。

本文件为实施任务书。本轮不修改代码、不采集正文或图片、不取得或变更任何授权、不自动提交及推送Git。功能完成并验收后用户统一提交与git push。

用户已明确选择：在当前新闻列表上用弹窗阅读，不另开独立页面或浏览器标签。本文“阅读视图”均指阅读弹窗；许可分层、正文保真和来源核对要求保持。

## 1. 基线与交付范围

目前新闻列表支持类别、商业地区、来源和分页，点击标题跳转原站，详情为显示摘要/正文节选的弹窗。最近验收记录为327条新闻、9个已启用来源；SpaceX、Blue Origin和Skyroot仍未接入，不能因本次改版改变其阻塞结论。

此次交付：扩展现有详情弹窗为连续阅读弹窗、内容许可分层、有限且经过核对的正文/图片样本、来源和图片署名、可定位段落、关闭后列表状态保持、阅读范围及版本信息、为未来AI预留的服务端上下文。

不交付：全部历史文章全文镜像、所有来源转载授权、自动翻译、图片访问限制绕过、模型训练、真实AI问答或新闻全站爬取。AI问答仍按已有方案作为后续功能。

## 2. 正文和图片分别确定可用范围

### 来源展示规则

| 来源 | 本轮目标 |
|---|---|
| 国家航天局、中国载人航天 | 政府来源全文候选；核对文章来源与转载范围后才显示正文 |
| NASA | 美国政府机构来源，可列入全文候选；遵守其内容使用指南与第三方例外，不自动放行所有文章 |
| ESA | 政府间组织，归入其他机构；标题、来源/日期、原文链接 |
| 中科宇航、蓝箭、Arianespace、ispace、Gilmour等公司 | 标题、来源/日期、原文链接；不展示摘要、正文或配图 |
| SpaceX、Blue Origin、Skyroot等未接入源 | 原阻塞保持，不制造新闻条目，不为此次策略绕过访问限制 |

以上按人工确认的主体和来源清单配置，不以既有publisher_kind=agency、.gov/.gov.cn后缀或URL字符串自动判断所有转载权限。政府网站转载第三方报道与摄影作品仍须另核对。未获确认的政府文章同样降为标题＋原文链接，不先公开全文再补许可。

建议独立source_reading_policy（government_candidate/link_only）及文章许可状态，不改动现有地区、agency/company分类和筛选合同。即便其他机构素材允许某些使用，本轮也不自动扩大其站内展示范围。

“注明转载”不是一项通用许可。采用来源政策模板＋文章/素材例外核对，记录许可依据，不从网站公开、可抓取、RSS可读、免费科普或比赛身份推定全文授权。

| 状态 | 展示方式 |
|---|---|
| 政府候选正文与相关图片都明确可用 | 本站全文；图片仅在后续存储配置和单独许可条件具备时接入 |
| 政府候选正文明确可用，图片未明确 | 本站全文，不搬运未确认图片；图片到原文查看 |
| 政府候选正文许可未明确，或来源为其他机构/公司 | 标题、来源/日期、原文链接，不展示摘要、正文和配图 |
| 已获许可撤销或文章撤回 | 撤下相应正文/图片，保留适当状态和原文入口，不继续输出缓存全文 |

原规划中的事实导读/适当引用不是本轮其他机构或公司的展示模式。现有已存摘要不得因仍在数据库中就继续公开返回；不删除既有记录或改写历史验收结论，而由API和页面应用新的展示策略。

记录：text_permission、image_permission、translation_permission、ai_context_permission或等价的独立状态，许可条款/授权文件出处、权利人、适用用途、须保留的署名、第三方例外、核对人、核对时间与期限。状态至少区分待确认、符合已核对条款可用、明确授权可用、不可用/撤回。

源层面的许可不是该站每一幅图片都可用；新闻由第三方转载、图片由合作方持有时按实际权利人判断。不自动勾选翻译或第三方模型处理权限。

首批优先调查NASA自有新闻内容及逐图署名条件；不预先将全部NASA内容设为可复制。ESA正文与多媒体的使用条件不同，中国载人航天官方影像亦有独立规定。商业公司逐家核对，不将新闻稿形式当自动授权。

## 3. 页面设计

### 列表页

保留当前简洁行式新闻列表、分组、地区、来源、语言、发布时间精度和分页。可展示正文的政府文章提供“阅读正文”，打开阅读弹窗，另有“原文↗”；其他文章标题直接链接原站，不提供会重复标题的站内详情弹窗。

每条只增加一个轻量阅读范围标记：本站全文 / 原文阅读 / 暂不可用。仅政府文章可以显示当前审核范围内的摘要，link_only文章不展示摘要或配图。列表不加载整篇正文或原图。

### 阅读弹窗

保持同一视觉系统，扩展现有dialog容器。桌面弹窗外宽可约900px，正文最大宽约720—800px，16—18px字体、较宽行距；最大高度约85—90vh，正文区域独立滚动，顶部关闭按钮保持可见，不以三栏聊天面板压缩正文。手机按屏幕调整，可接近全屏弹层，但仍在当前页面内。

结构：关闭/返回列表 → 标题 → 来源/作者/发布日期/语言/内容范围 → 导读（有时）→ 正文 → 图片及各自说明/版权 → 原文链接和使用说明。打开时锁定背景滚动；关闭时保持原列表、已加载页、筛选及滚动位置，并将焦点返回触发元素。支持Esc关闭与键盘焦点约束，关闭不得重载整个列表。

授权正文按原始顺序显示标题层级、段落、列表、必要图注和简单表格。保留数字、单位、“预计/可能/不早于”等限定词；不自动简写为作者原文、不把英文全文伪装成中文原文。后续中文翻译若需要，必须另有允许范围并标“译文”。

图片用figure/figcaption，显示原始图注及核对过的credit，缩放适应屏幕、不剪掉含信息的图表。未取得图片使用范围时明确省略，不用装饰图冒充新闻原图。不展示新闻源网页导航、广告、表单、脚本或全站品牌界面。

政府文章正文不可用时可在弹窗说明原因并提供原文入口，不能显示摘要却标“全文”。其他机构/公司不打开站内正文弹窗，直接通过原文链接阅读。原站打不开时不声称已取得完整内容。

### 导航和阅读状态

可继续用hash记录弹窗状态，例如#news/article/文章ID，与现有#library等入口兼容；该地址只在新闻列表上打开对应弹窗，不切换到独立阅读页面。浏览器刷新可重新读取当前许可并打开弹窗，前进/后退可打开或关闭弹窗。服务端继续以article_id提供数据，不通过URL片段接收待抓取外站地址。

从列表打开时保留类别、地区、来源、已加载页与滚动位置；关闭时恢复背景滚动，优先保持现有DOM而不是重新请求全部列表。直接访问文章链接时在新闻默认列表上打开弹窗，关闭回到默认列表；不能一律调用history.back()导致用户离开网站。链接不存在、全文取回失败、权限变化和图片失败分别在弹窗中处理，不清空已有新闻列表。

## 4. AI入口的衔接范围

AI功能上线后，阅读弹窗可提供“向AI提问”，携带article_id而不是前端拼接任意正文。可保留选词/段落选择的界面位置，但本任务不实现收费模型调用。

当前模型服务未接入时，AI入口隐藏或明确为尚未开放，不跳到固定示例冒充这篇新闻的回答。数据接口可提前实现read_scope与content_version，供下一阶段使用。

未来AI上下文由后端按本轮材料范围生成：政府正文许可及模型处理范围均允许时使用正文；link_only新闻只有标题、来源与发布时间，不能取隐藏的旧摘要或后台私存全文冒充AI已读取原文。用户从原站阅读后可提问通用术语，AI用知识库解释并说明未获得该新闻正文，具体事件细节不推断。本阶段不实现任何AI调用或上下文服务。图片也不送入视觉模型。

每段有稳定paragraph_id，引用标为“本站正文第X段”或“本站展示节选”，与原文页码/段落位置区分。正文或许可版本变化后旧缓存失效，切换新闻必须切换问答上下文。

## 5. 数据与API

保持现有articles ID、URL、first_seen_at、新闻采集状态、回填任务与失败队列。全文不塞入现有列表查询的articles.*，新增独立文章内容表与素材表，采用幂等迁移并先一致性备份。

article_contents建议记录：article_id、reading_mode、原文版本/获取时间、text_blocks、正文语言、content_version/hash、内容获取状态、许可记录ID、许可状态/版本。reading_mode可为full_text/link_only/unavailable。旧记录默认link_only，政府文章也须逐项审核后升级，不在迁移时默认允许全文。

text_blocks使用受控结构，如heading、paragraph、list、table、figure_reference，每段保留ID与原始顺序。采用纯文本字段和安全渲染，不直接把源HTML插入DOM；不接script、iframe、事件属性、任意style或未知嵌入代码。

article_assets记录对应文章/段落、原始地址、经核对的托管地址、格式/尺寸、图注、credit、权利人、许可记录、状态与版本。不可用图片不在公开API暴露可显示资源地址。

接口：

- GET /api/news保持轻量，补reading_mode；link_only条目只返回元数据，兼容字段summary可置空，不返回旧摘要、正文或图片。
- GET /api/news/{id}同样执行来源展示规则，不能只在前端隐藏内容而让此接口继续返回完整旧摘要。
- GET /api/news/{id}/content只对full_text且许可仍有效的政府文章返回正文块；link_only返回明确模式和原文链接、空正文与空图片，不泄露数据库旧内容。撤回及配置变化同时作用于API与缓存。

公共接口没有任意URL取回、正文重新采集或修改许可能力。AI内部上下文组装为受控服务函数，不能绕过公开展示限制自动读取未确认材料。

## 6. 内容获取与图片存放

先做3—5篇许可明确的政府文章正文样本，另选其他机构和公司条目核对link_only展示。图片按当前后置约定处理。每篇许可依据必须核对，测试模式可用自有内容构造撤回/失败状态，不能把模拟稿件混进正式新闻列表。

站点正文解析器按真实文章结构配置，只提取文章本身，清除页头/页尾、推荐、广告和分享区。正文与原文人工逐段核对；如果主要内容在图表或特殊结构中而解析失败，不标全文完整。

版权和允许抓取方式确认后再获取正文；检索能力或抓取成功不产生许可。不得绕过地区封锁、安全检查、验证码、登录或图片访问限制；原有SpaceX等阻塞仍记录。

本轮对样本采用显式维护任务，不在用户每次打开文章时实时抓取，不在Web启动自动爬全部327条，不重新启用深度历史回填。未来启用增量正文更新也只针对已批准来源与范围，并设置总请求预算与并发上限。

图片经逐张人工授权核对后保存到/data/news-images/<article_id>/<asset_id>/<内容哈希>.<格式>，该目录位于新闻持久卷内，不放入静态网站目录。图片接口每次检查文章当前版本、正文许可和图片许可，再返回文件；撤回或过期立即停止新请求，旧版本图片不会混入新正文。容器重建继续使用同一卷。

正文数据库与图片文件必须一起一致性备份和独立恢复。先暂停审核任务与新闻采集，再生成SQLite备份及其引用图片快照，原卷保留。上传到OSS的PDF下载流程保持。

不使用任意图片代理或去referer绕过防盗链。图片获取只允许已核对的主机/路径，重定向重新校验、禁止内网地址、限制响应体与总预算。只接常规JPEG/PNG/WebP并核验实际格式，不原样公开未知SVG或HTML。

图片最大显示尺寸、编码质量、每图/每篇总字节预算按真实样本设定，过大则标为尚未适配而不是默默删改信息后宣称完整。图中含科学数据时确保文字仍可辨，保留原图链接与credit。

浏览器图片延迟加载、有固定尺寸和失败占位。服务器不做在线全文OCR、视觉模型或实时图像压缩；批量图片处理可在本机/维护任务完成。

## 7. 实施顺序与交付节点

1. 许可调研：编写“新闻正文与图片使用清单”，确认样本、许可范围、逐图credit及允许获取方式。不把来源名字直接作为放行条件。
2. 数据与接口：独立内容表、结构块、来源展示策略、许可分层、版本和撤回处理；旧记录默认link_only，政府正文经核对后启用。
3. 页面改造：现有详情弹窗扩展为阅读弹窗、关闭后列表状态保持、来源与范围标注、段落/图片、安全渲染和手机阅读。
4. 样本接入：3—5篇真实样本解析及逐段/逐图核对，未明确来源继续原文链接，不要求所有新闻源获得相同转载范围。
5. 部署与验收：更新服务器，保留新闻数据、调度及电子书下载；当前浏览器网络限制由用户在国内环境测试，不为本任务改变SSH/防火墙。

本功能节点为“新闻阅读弹窗＋许可分层＋经过核对的正文样本”，不是所有新闻全文覆盖。验收通过后用户统一Git提交和推送；随后实施新闻关联AI。

目标约2—3个工作日，取决于解析结构与许可确认；待核对来源不阻塞标题＋链接模式。许可尚未明确时可先实现结构与自有测试样本，但不能宣称已上线该源完整新闻。

## 8. 验收标准

- 既有新闻数量/ID/首次入库时间、来源状态、历史任务与失败队列保持；类别、地区、来源与分页仍正常。
- 有许可样本正文与原文顺序/数字/单位/限定词一致，图片与文章对应，credit和使用依据可追溯。
- 政府正文允许图片未确认、link_only、获取失败、撤回等状态正确；其他机构与企业的API、页面和缓存不公开旧摘要、正文或配图，标题、日期及原文链接仍正确。
- 不存在脚本执行、任意HTML嵌入、任意URL抓取/代理或跨文章引用混用；原文链接与模型未开放状态真实。
- 弹窗关闭/Esc/键盘焦点、背景滚动锁定与恢复正常；复制文章链接、刷新及前进后退能正确打开/关闭对应弹窗，关闭后列表筛选、分页及位置保持。手机连续阅读及图片失败处理可用。
- 列表不下载所有正文/原图，正文图片按需加载，实际内存及流量可记录；文件下载仍由OSS直接提供。
- 容器重建后正文版本及许可记录仍在；备份独立恢复；原资料下载及新闻增量采集不退化。
- 服务器验收与人工浏览器/内容核对分开记录。没有取得全部来源全文或没有运行AI时，不扩大完成结论。

交付：代码PR或变更集、许可调研记录、样本核对、固定测试、数据迁移/回退说明、部署验收与未解决清单。公共转载与内部模型上下文的许可边界须如实标明。

## 10. 人工审核后台

单管理员独立账号，无默认密码；服务器命令交互设置密码并保存慢哈希。使用独立后台服务，服务器仅127.0.0.1:8090可访问，通过SSH转发到本机18080，避免在当前公共HTTP站点输入密码。会话过期、登录失败锁定、CSRF、审核日志和草稿版本冲突检查均启用。

工作流：按既有article_id选择政府新闻 → 有预算的官方路径抓取形成私有待审草稿 → 编辑正文并核对原文、许可依据与第三方例外 → 勾选正文许可/完整性 → 发布当前版本。抓取不自动授权，其他机构与企业仍原文阅读，不扩大候选清单。

图片候选来自该草稿中的已核对主机/路径，逐张填写许可依据、权利人、图注与credit后提交后台任务。仅已发布且与草稿一致的正文版本可以关联图片；每版本最多5张、每张8MiB、24百万像素以内，连续处理避免内存峰值。失败可人工重试，不删除历史正文。图片任务重启后显示失败而非偷偷重发。

已解码或已被读者保存的图片无法从其设备追回；本站对后续请求停止提供，打开中的弹窗通过版本复查更新。首版不提供图片裁剪、自动压缩、任意URL代理或模型处理。
