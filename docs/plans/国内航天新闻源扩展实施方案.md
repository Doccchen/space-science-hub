# 国内航天新闻源扩展实施方案

日期：2026-10-05。性质：交给实施 Codex 的开发任务书。本轮只制定方案，不修改功能代码，不进行服务器部署或重复验收。

## 1. 当前基线与目标

依据《新闻部署验收记录》：NASA/ESA真实采集、幂等入库、API来源筛选与游标分页、单源故障历史保留、容器重建后数据保留已通过；浏览器基本使用由用户确认。当前19条、首批20条，前端“加载更多”点击尚未验收。公网国内访问可用，国外不可达原因未定位，不因本次扩源重建网络配置。

目标：在保留现有新闻及ID的基础上，加入国内官方航天机构和商业航天公司官方新闻，中文内容原文展示。以少量稳定来源完成闭环，不把全部行业来源接入作为Agent开工前置。

本轮不开发：公众号、全网搜索、第三方聚合、自动翻译、事件聚合、图片代理、资料下载或真实Agent。

## 2. 首批来源与已核对的入口

| 来源 | 发布性质 | 已核对入口 | 初始范围 |
|---|---|---|---|
| 国家航天局 | 官方机构 | https://www.cnsa.gov.cn/n6758823/n6758838/index.html | 要闻动态 |
| 中国载人航天 | 官方机构 | https://www.cmse.gov.cn/xwzx/zhxw/ | 综合新闻 |
| 中科宇航 | 商业航天公司 | https://www.cas-space.com/list/6.html | 公司自发新闻，排除同页媒体转载外链 |
| 蓝箭航天 | 商业航天公司 | https://www.landspace.com/news.html?catid=1&mao=1 | 最新新闻，排除媒体报道及其他栏目 |

以上官网/栏目已通过公开网页核对，未从目标服务器验证HTTP响应、HTML结构、解析规则与日期字段，不能直接写为“自动采集已可用”。本轮没有确认四家是否提供原生RSS，不据此断言不存在RSS。优先使用发现且验证的官方RSS/公开接口，否则采用具体栏目的HTML解析。

国家航天局新闻详情可见标题、发布时间和内容来源；这些字段需分别保存，发布站点不一定是原始报道作者。中科宇航要闻页同时包含公司新闻与外部媒体报道，首轮只接本公司域内的自发新闻；页面产品、招聘、资料下载、媒体外链不纳入采集。

本次还观察到国家航天局个别列表日期与详情发布时间不同，说明列表日期可能不是相同语义的时间；部署解析前必须用具体样本核对，以详情明确的发布时间为准并保留日期出处，不能以任务发生日期或简单排序猜测替代。

实施顺序：先验证四源并记录可用性 → 国家航天局及中国载人航天 → 能最先稳定接入的一个公司 → 第二家公司。某源阻塞时记录并暂缓，不能因一个官网的特殊结构延误其余来源；未成功的源保持禁用，不能将“已配置”当成已接入。

## 3. 第一项任务：服务器来源验证

每源至少核对一个列表页及三个不同新闻详情（可用条目不足时记录原因）：

- HTTP状态、最终跳转地址、编码和响应大小。
- 列表中标题、日期、详情链接与栏目边界。
- 新闻详情的标题、发布时间、原始内容来源、可用摘要或正文开头位置。
- 列表与详情日期冲突时优先明确发布时间字段，保留异常记录，不取正文中任意任务日期当发布日期。
- 官方RSS/公开接口是否存在及实际可用性；网页是否仅给JS外壳。

交付《国内来源接入调研记录》：入口、实际采集方式、成功样本、字段位置/选择器、日期精度、跳转范围、访问及内容使用约束、待解决问题。解析选择器必须来自实际返回样本，不能由本方案猜测。

普通HTTP不能稳定获取的源，先记录阻塞；如果确有公开、无需绕过限制的官方数据接口，可验证后使用。首版不新增常驻浏览器或RSSHub，不绕过验证码和访问限制。人工链接录入如需兜底，另标人工方式，不宣称自动采集成功。

## 4. 后端采集改造

当前backend/news.py以RSS为固定入口，SOURCES只有nasa/esa。扩展为有限的来源配置与两种明确适配器：RSS、指定栏目HTML。配置由开发人员维护，不开放访客新增URL能力。

共用流程：受控请求 → 来源适配器解析 → 统一记录 → 链接/日期校验 → 幂等入库 → 来源状态更新。每家HTML源独立解析，不做未经验证的全站通用抓取器；需要时引入BeautifulSoup等轻量库并固定依赖版本。

限制：

- 默认每60分钟检查列表；不同站点并发上限2，同站详情请求串行并适当间隔。
- 首轮每源最多获取列表前10条；普通轮只补充新记录和确需更新的详情。后续历史回填作为手动运维任务，不一次遍历多年新闻。
- 超时、响应大小、重定向、来源域名限制、单源故障隔离继续有效。仅抓审核过的栏目与详情路径。
- 无来源摘要时，允许使用正文开头的有限纯文本节选并明确标注“正文节选”；不调用LLM编写新闻摘要。可用文本为空时明确显示“未提供摘要”。
- 不下载/代理图片、不在页面发布全文。HTML必须清理后作为文本输出，不能直接注入网页。
- 同一事件不同机构报道分别保留；只有同来源同文章标识/规范化URL才执行去重。
- 正常采集只依赖来源本身，不根据正文或导航发现新的站点。

## 5. 数据迁移与API

必须兼容现有卷与数据库，不清空表、不重新生成已有文章ID。先一致性备份，新增字段采用可重复的迁移步骤，再进行新源初始化。

sources建议新增：collector_kind、region（国内/国际）、publisher_kind（官方机构/商业公司）、enabled、栏目入口与已审核的详情路径范围。现有NASA/ESA回填“国际、官方机构”，四个新源配置分别明确类别。

articles建议新增或明确：lang（新增中文zh，既有英文en）、summary_kind（来源摘要/正文节选/无）、content_source（原文“来源”或署名，缺失可空）、published_precision（日/分钟/秒，缺失单独状态）。旧记录回填规则写入迁移说明。

不能继续让新增中文文章采用数据库默认en。国内页面日期若只有日，前端只显示年月日，不补成可见的00:00。API可保留内部排序用的约定时刻，但必须携带精度；约定北京时间转换UTC的规则明确记录。缺失发布时间仍不以获取时间代替。

GET /api/news/sources返回可供前端生成筛选器的来源及类别信息，不暴露原始错误详情。禁用来源状态明确，不与正常但暂无文章混淆。

GET /api/news增加可选类别过滤，和现有source过滤共同定义行为；游标绑定所有有效筛选条件，切换类别或来源必须清空游标。维持现有日期倒序、缺日期后置及ID稳定排序。

## 6. 前端展示

保留已认可的简洁布局，不将六个以上来源全部展开为一排按钮。使用两层轻量筛选：

第一层：全部 / 国内机构 / 商业航天 / 国际机构。

第二层：按当前分组动态生成具体来源选择器。来源来自API，不能继续硬编码NASA/ESA。地区及发布性质分开存储，首轮“商业航天”只含已接入的国内公司；将来加入国外公司时无需改变数据结构。

新闻显示：标题、发布时间（按精度）、发布站点、来源性质、中文或英文原文、有限摘要/正文节选与原文链接。商业公司文章标签为“企业动态”，不笼统标成官方机构通告；原文的“领先”“最低成本”等自述不升级为本站认证结论。详情页可显示原文内容来源/署名，保持发布站点和原始内容来源的区别。

API获取失败继续保留已加载内容；来源采集失败与前端请求失败分别提示。恢复全部筛选与更换分组后分页顺序不混入旧结果。

## 7. 测试与验收

固定样本测试：四家真实结构的最小HTML样本（保留必要来源说明）、中文编码、相对URL、列表重复链接、正文日期与发布日期区分、日期缺失、中文lang、公司页面混有媒体外链、选择器失效、异常重定向、摘要脚本清理。

迁移测试：现有数据库的文章ID、URL、first_seen_at与已有记录数量保持；迁移重复执行安全；旧API过滤不退化；新增字段缺失时可兼容；增量去重有效。

服务器验收：

1. 每个已启用的新源至少三条真实新闻，手工抽查标题、日期、链接、发布性质与语言；未启用源记录原因，不算通过。
2. 按相同载荷重放或重复采集不新增重复记录、也不改变原记录ID。
3. 现有NASA/ESA记录保留且继续更新；新源失败时不影响它们。
4. 新分组、单来源筛选与API分页正确。用足够的真实/明确测试记录补验前端“加载更多”点击；测试记录不得混进正式新闻列表。
5. 重建容器后旧新闻与新增中文新闻仍在；备份可恢复。
6. 记录增量采集耗时、请求量和内存峰值，保持当前2核2G测试环境可运行。

交付：代码PR、来源调研记录、数据库迁移与回退说明、新增测试结果、服务器验收记录。某来源仍阻塞时按实际成功列表说明，不写“国内四源全部完成”。

## 8. 执行边界与预计节奏

实施Codex具体编程和测试，用户执行必要服务器命令，规划方审核结果。本方案不授权清库、删除卷、重配SSH/防火墙或公开第三方资料全文。

目标节奏：半天至一天做来源验证；一至两天完成适配器、迁移与动态筛选；半天服务器验收。该估计依赖官网结构与服务器访问，不保证所有四源同日完成。

扩源与验收完成后立即转向真实科普Agent，后续其他机构与商业公司列入待办，不持续扩大本阶段范围。
