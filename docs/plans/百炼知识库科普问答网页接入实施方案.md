## 1. 接入路线

网页提问 → 现有FastAPI → 用户已发布的百炼应用API → 应用内部知识库检索/模型回答 → 后端规范化并检查回答与引用 → 网页展示。

沿用已经搭好的云端应用与知识库，不再开发本地embedding、NumPy向量索引或第二套知识库。普通模型聊天接口不自动代表调用已配置知识库的应用。知识库与模型配置在百炼维护，网站负责界面、请求控制、会话隔离与结果展示。

先在服务器用一个实际问题验证：应用能被API调用、确实关联正确知识库、来源可返回、回答与控制台相符。控制台调试成功不等于草稿配置已经发布到API，必须核对已发布版本。

当前目标采用知识问答接口：POST https://{workspaceId}.cn-beijing.maas.aliyuncs.com/api/v2/apps/knowledge/chat 。agent_id放在parameters.agent_options.agent_id，问题及历史放在input.messages，按接口要求stream=true。服务必须已发布，密钥和业务空间匹配。

不要使用经典应用completion路径、普通模型聊天接口或经典应用output.text/doc_references解析器。应先用实际返回样本确认该服务与官方知识问答协议一致，再实现适配。

## 2. 首版功能边界

必须完成：独立输入框、真实知识库问答、有限连续追问、新对话、回答依据、资料不足与失败提示、超时/限流、用量记录。

不实施：新闻自动带入、新闻问答按钮、实时联网搜索、任意文件上传、在线PDF读取、双版本文章改写、知识库管理后台、更多模型自动切换。新闻和资料下载保持独立现状，当前固定月球示例不能继续作为真实回答。

## 3. 百炼控制台准备

1. 确认已知agent_id、业务空间、API入口和服务已发布版本。
2. 检查发布版本确实关联本次专属知识库，文档解析/索引完成。
3. 配置科普风格、知识库优先、依据不足拒答、保留数字/单位/条件；不允许无依据补写精确参数。
4. 验证实际知识问答流能返回检索工具的结构化来源与正文，并核对回答引用方式。经典智能体的doc_references不是当前接口的默认解析结构，不凭提示词生成来源。
5. 使用三类问题实际测试：知识库明确支持、换一种表达、知识库没有依据。检索不到时不得默认转成自由知识回答。
6. 确认没有首版不需要的联网/外部插件；需要澄清时追问，超范围问题说明知识库范围。

用户凭据在本机/服务器环境配置，聊天与Git中不提供API Key。aid服务ID、知识库ID和业务空间ID作用不同，不混用；agent_id不直接代替域名中的workspaceId。

## 4. 页面与交互

现有“科普Agent”栏目改为独立问答页，保持已选浅色冰蓝风格。页面说明“基于本站专属知识库回答”，并简要列出实际知识库覆盖主题，不能宣称航天百科全覆盖或全网最新。

结构：简短介绍 → 2—3个由真实知识库覆盖的示例问题 → 问答区 → 输入框/发送 → 新对话。先简洁单栏，不保留原固定“专业摘要/科普版本”切换、固定导出或演示材料输入流程。

回答按段落清楚展示，来源卡片可展开：文档名称、可取得的页码、有限被引用片段，以及已审核可公开访问的原文链接。没有链接只展示来源名称/位置，不编造下载链接；没有页码不生成页码。

区分初始、准备回答、回答成功、资料不足、需要澄清、服务失败、限流与配置未启用。未启用时明确未开放，不返回固定示例冒充模型。

切换到新闻或资料页面不将内容自动发送给百炼。输入内容以纯文本发送，模型返回文本/受控Markdown展示，不执行原始HTML、模型建议代码或任意链接动作。

## 5. 后端适配与引用检查

建议新增BailianAppClient及独立AI路由，使用现有httpx异步HTTP；不强制加SDK。提供商地址、应用ID、工作空间及请求变量只来自服务器配置，访客不能选择调用任意应用或模型。

客户端只发送问题和本站会话标识。后端按已核对API构造请求，读取回答、完成状态、会话、引用、请求ID与用量，规范化成本站格式。具体字段由真实调用样本确定，不根据不同产品的文档混写一个请求。

当前知识问答接口仅支持SSE，上游请求必须stream=true；不能为了完整回答模式把上游stream设置false。首版后端读取SSE并缓冲最终回答，检查后向本站返回完整JSON，网页仍可显示真实等待状态。逐段向浏览器转发后续另评估。

解析要处理SSE事件边界、跨网络chunk拆包、心跳/空包、业务error帧以及完整结束条件。只将generating阶段当最终回答，planning及工具帧不显示为科普正文，更不展示模型思考。检索返回结构可位于工具帧的additional_kwargs.extra_json.docs，按调用ID关联，具体字段以真实脱敏样本验证。没有可靠结束、途中error或断流不能把半截回答当成功。

记录平台request_id和最终结算用量，不重复相加快照型计数字段；HTTP200不代表流内无业务错误。资料引用与回答编号映射以实际协议验证，不假定每个检索命中片段都是最终答案引用。

知识库事实性回答应有适用版本返回的有效引用；检查模型引用编号能映射到本次实际引用记录、记录有具体文本、引用标识/文档信息符合预期。引用存在不保证支持结论，真实评测继续人工核对关键事实。

若未返回引用：区分明确拒答、普通寒暄/澄清与无证据的事实回答。无证据事实回答不标成“基于知识库已验证”；优先修复百炼配置/接口，无法确保知识库支持时以资料不足或无法可靠回答处理，不直接放行模型自由生成。

文档链接可能为null或平台私有地址，这是正常可能情况；只把公开且批准的资料地址显示为可点击链接。私人链接、临时访问凭据与完整内部返回值不放前端或日志。

## 6. 会话隔离

当前知识问答API不保存会话状态，也不返回session_id；每次请求需传入messages历史。本站后端保存并重组有限轮次，不使用经典应用session_id机制。

网站使用不可预测的本站conversation_id，绑定访客与有限历史。不能让匿名用户共享历史，不能接受访客提交其他会话的历史或系统指令。会话过期、新对话和服务配置更新时重新建立，历史AI答案不作为知识库原始证据。

首版最近3—5轮或明确长度上限；超过上限提示新对话。采用适当cookie/访客标识与过期机制，按当前HTTP测试/未来HTTPS部署配置验证，不把后台管理员登录与匿名问答会话混用。

用户切换/清空对话时，旧请求即使晚返回也不能写入新会话。取消前端请求不保证供应商已停止计费，应记录已发起请求并防止重复点击。

## 7. 配置、限流与运行

配置示例字段：AI_ENABLED、BAILIAN_AGENT_ID（当前aid-066ddd0b6e1e44d6bf7d620e0ac7c060）、BAILIAN_WORKSPACE_ID（当前llm-ep9bqc9mnw50k8e0）、BAILIAN_API_BASE（https://llm-ep9bqc9mnw50k8e0.cn-beijing.maas.aliyuncs.com，首次调用前核对控制台）、DASHSCOPE_API_KEY、服务配置版本、总超时、并发上限、日额度。不把endpoint由客户端输入。

应用ID、API地域与密钥/工作空间必须匹配；不采用北京、新加坡、知识库网关与经典应用接口混合配置。模型与知识库费用按实际发布应用、账户和使用量核对，不能认为控制台能问答就免费。

保持现有Docker及FastAPI，初始同时处理AI请求最多2个。问题初始上限约1000—1500字符、最大历史和回答长度有上限，总等待时间可先约45—60秒并实测调整。排队满提示稍后重试，不挤占新闻API工作。

设置每访客/IP每分钟及每天限额、全站每天总额度；默认值由测试预算确认。使用可信的网络来源，不接受任意X-Forwarded-For作为身份。用量与日计数持久化，重启不能无限重置额度。

API错误区分鉴权/发布或配置不符、429、上游超时、响应格式问题；不给用户原始内部堆栈或密钥。模糊网络超时不盲目重试POST，以免上游已处理造成重复收费。限流不解释为知识库缺资料。

首版不跨访客缓存多轮回答。知识库更新与应用发布版本目前没有确认自动版本接口，采用人工维护的配置版本并重新建立会话；不假装能自动得到完整知识库版本。

## 8. 实施任务

1. agent_id和业务空间已提供；核对上述构造地址与控制台API示例，用户在服务器配置密钥。控制台确认发布及知识库来源返回，固定3—5个实测问题。
2. 从服务器调用应用，保存脱敏请求/响应样本；确认知识库调用、引用、拒答与会话机制。
3. 实现异步应用适配器、本站POST /api/ai/ask、GET /api/ai/status及会话管理；增加限流、并发、超时与规范化错误。
4. 将独立AI页面改为真实问答，替换固定样例；完成新会话和晚返回隔离、来源卡片及无依据提示。
5. 配置Compose环境变量，回归新闻及资料下载，服务器升级并进行真实问答/用户浏览器验收。
6. 交付AI接入验收与未解决清单。功能完成并验收后再由用户提交与git push；不自动创建提交或推送。

目标约2—3个工作日，取决于应用类型、调用权限和API引用能否正常返回。第一步先把真实应用响应验证清楚，不先实现本地知识库替代用户现有配置。

## 9. 验收

- 选至少20个真实问题，包括明确可答、同义表述、追问、模糊概念、资料不足、诱导编造与注入。预期依据由人工建立。
- 明确可答问题的解释忠实、易懂且有真实知识库引用；编号不存在、来源不支持或精确参数编造需修复，不以API200当答案验收通过。
- 知识库缺失应拒答/澄清，不由模型常识补出肯定结论。普通寒暄与接口失败有独立状态。
- 两个独立访客/会话互不影响，新对话与过期会话正确，取消/切换后晚返回不污染新问答。
- 密钥只在服务器，前端网络请求不直连百炼、不带Key；无任意应用/endpoint覆盖或原始HTML执行。
- 限流、上游429/超时、配置未启用/鉴权失败、无引用/错误引用、会话过期及响应被截断有固定测试。
- 网站新闻、阅读弹窗、权限状态及OSS资料下载保持；AI异常或禁用不使整个网站不可用。
- 真实服务器记录应用配置版本、响应时间、用量及资源；用户在国内可访问网络验收。控制台测试、自动接口测试和浏览器测试分别记录。
