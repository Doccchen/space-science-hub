# 实施分工与近期任务

更新：2026-10-05。

## 分工

规划与审核方：讨论需求、制定实施方案、拆分任务、审阅交付与验收证据。

实施Codex：按已确认任务编程、测试、打包及部署，交付变更与实际验证结果。未授权时不改变范围，不将固定示例标为真实Agent。

用户：决定产品方向，完成账户登录验证，保管服务器密钥及模型凭据；自动化连接不可用时执行准备好的服务器命令并提供结果。

## 当前已知环境

阿里云轻量Ubuntu 24.04.2测试服务器，2核2G规格，实际系统总内存约1.6GiB；可用约1.2GiB，根磁盘剩余约35GB。Docker29.1.3与Compose2.40.3已安装。

NASA/ESA feed在服务器返回HTTP200；Docker Hub测试镜像超时，ECR官方Python镜像已成功拉取。用户提供的digest为sha256:02108f5d322dd89f1c9e552442c25acb0543dfdbc455693a5599624f20d9155d。构建前核对对应镜像与服务器架构。登录信息与密钥不存仓库文档；以部署人员的本地配置为准。

## 第一阶段：服务器新闻闭环

目标：在测试服务器运行现有新闻模块并形成可核对的验收记录。

范围：依赖与镜像构建、SQLite持久化、官方RSS采集、列表筛选与分页、详情原文链接、采集状态、失败保留历史。

步骤：确认工作目录和已有服务 → 固定基础镜像与依赖 → 校验Compose → 构建并启动单worker → 首轮采集 → 测试页面与API → 验证重复采集及容器重建 → 记录结果。

验收：

- 至少NASA和ESA两源有真实记录，字段与原文相符。
- 重复采集不重复入库；一个来源失败时已有内容仍可读取。
- 来源筛选、加载更多、发布时间缺失状态正常。
- 容器重建后数据库仍保留；有可恢复的一致性备份。
- 记录版本、命令、日志、健康检查与实际资源占用，不只提交“部署成功”。

边界：不开发资料下载、不扩大来源、不接公众号、不进行事件聚合、不开放无鉴权采集操作。默认本机端口与SSH转发测试；公开访问另行确定入口和HTTPS。

## 第二阶段：真实科普Agent最小闭环

先制定单独实施方案，再进入开发。最低交付为一篇有权使用的真实材料 → 专业摘要及科普版本 → 可定位依据 → 参数与限定词核对 → 资料不足处理。

不以提示词和低温度宣称杜绝幻觉。输入解析、证据结构、输出校验、评测案例、模型预算与流式展示方式均需在开工前明确。
