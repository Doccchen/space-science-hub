# 新闻科普 Agent 开发方案

日期：2026-10-08。状态：方案草案；本次仅编写开发文档，不修改功能代码、不调用收费服务、不部署服务器。用户最终目标：围绕网站新闻进行连续提问；网站缺少全文时读取发布方原文；科普背景优先使用用户航天知识库；保存解读并接入独立解读库。

## 1. 已确认基础与未验证事项

- 已创建并发布 Flow Agent 下的 Agent 2.0“航天新闻科普助手”。截图显示 DashScope API 首轮及携带 session_id 的追问都返回 HTTP 200；回答能关联先前新闻。应用 ID 以控制台复制的完整值配置，不依靠截图转录。
- 截图不能证明知识库实际召回成功。回答中的“知识库指出”不等于结构化引用；原始完整 SSE、结束条件、引用与用量结构仍需取得脱敏样本并核对。
- 当前通用 AI 使用 backend/bailian.py 中的知识问答接口 /api/v2/apps/knowledge/chat，与新闻 Agent 的 /api/v1/apps/{app_id}/completion 不同，不直接替换当前客户端。
- 已有 reading.py 正文版本与展示状态、review_capture.py 正文提取、publisher_fetch.py 来源域名/DNS/重定向/请求预算限制，以及新闻阅读页 news-reader.js。
- 当前 Publisher 仅列明 NASA、ESA、国家航天局、中国载人航天等范围；已有解析器也不覆盖全部新闻来源。列表抓取成功不代表具备全文读取能力。
- 已有 AI 会话、额度、运行配置与私有管理后台可参考复用，新闻能力独立配置、独立开关，避免改变通用问答合同。

## 2. 交付范围

第一期交付完整单篇链路：新闻页入口 → 获取原文 → 基于正文与航天知识库生成解读 → 连续提问 → 保存个人会话与解读草稿。包括公开可达且带鉴权的新闻读取 MCP、失败状态和新闻隔离；不能以只粘贴正文的演示视为整期完成。

第二期交付：后台解读预览、发布、撤回、知识库同步与历史检索。首期不自动把所有生成回答和对话写入解读库。

第三期按需扩展：跨新闻比较、补充来源的全文解析、长篇 PDF/动态页面适配、自动生成策略。网站每个已登记来源都应登记支持状态；未适配来源明确提示，不能声称所有原文均可读取。

不增加任意网址输入、用户文件上传或无限自动抓取；不绕过登录、验证码和付费限制。按现有实际新闻来源逐项适配。

## 3. 架构与分工

```text
新闻页 → 网站新闻对话 API → 百炼新闻 Agent
                │                   ├─ 航天知识库：原理与背景
                │                   ├─ 解读库：已发布历史解读（第二期）
                │                   └─ read_news MCP → 网站原文服务
                │                                       ├─ 已有正文版本
                │                                       └─ 发布方原文抓取/缓存
                └─ 会话、任务、用量、解读存储

后台发布解读 → 同步任务 → 文档上传/解析/索引 → 百炼解读库
```

核心原文服务可被网站内部与 MCP 调用，共用缓存、来源判断和状态。首期联调可先由后端取得正文并传给 Agent，验证问答；随后接上 MCP 原文读取工具，完成最终链路。

网站负责：新闻绑定、原文读取、会话所有权、任务去重、超时、额度、保存、同步。百炼负责：模型配置、提示词、知识检索及工具调度。原文抓取成功不自动改变公开全文展示策略。

## 4. 原文读取与 MCP 合同

工具：read_news(article_id)。只读数据库登记的原文链接；不接受模型提供的新 URL、任意主机或本地路径。生产请求还需服务鉴权与可信调用上下文；上下文必须绑定本次新闻范围和过期时间，传递方式在百炼 MCP 联调中确认，不能仅靠静态工具密钥信任模型传入的 ID。

流程：检查新闻是否仍可访问 → 检查 AI 上下文使用策略 → 复用完整正文或有效缓存 → 建立去重读取任务 → 按 source_id 选择抓取器及正文解析器 → 检查完整性 → 返回段落及版本。

建议工具响应：article_id、title、source_id、original_url、published_at、fetched_at、content_version、read_status、completeness、language、blocks、warnings。blocks 使用稳定段落编号，表格和列表保持结构；正文不得只保留段落而遗漏关键表格。

状态至少包括 full、partial、pending、unavailable、unsupported、blocked、withdrawn。完整性判断基于结构/覆盖检查，不只靠字数。检测登录页、反爬页、错误页、空正文、PDF及特殊结构；超过上下文限制时不能静默截断并宣称读过全文。长文按段落分段提供，返回总段数和已读取范围；必要时新增 read_news_sections 工具作为长文适配。

来源顺序：先验证 NASA、国家航天局、中国载人航天已支持路径，再适配 ESA、中科宇航、蓝箭航天及实际启用的其余来源。采用来源登记表列明域名、正文选择器、重定向目标、完整性检查及样例测试；来源名称或请求页改变时返回可诊断失败。

AI 上下文读取与公开转载分开。现有 permissions.ai_context 字段需有明确来源策略与审计，不把 pending 改写成 granted。用户已要求补读原文，实施时将策略落地为实际来源配置，不以显示 link_only 直接判定禁止 AI 读取，也不因为网页可访问就认定可以永久转载或入库全文。解读库默认保存解读与来源信息，不自动收录原始全文。

缓存保存内容散列、抓取时间和失效状态。有效缓存内复用；新闻修改、撤回或管理员刷新时更新版本。读取失败短期缓存并冷却，避免每个追问重复访问原站。

MCP 使用百炼支持的 HTTP 传输协议及 SDK，复用 FastAPI 或单独轻量服务；部署前确认现有服务器的 HTTPS 域名入口、鉴权、反向代理和百炼连通性。当前截图只验证应用 API，不代表 MCP 可达。工具任务超时短于应用总超时；超时返回 pending 状态并指导稍后重试，不把模型请求长期挂起。首版不强制浏览器自动化，动态来源按需求另加适配。

## 5. 百炼调用与回答规则

新增独立 NewsAgentClient，使用 httpx 调用已发布 DashScope 应用，以控制台实际示例配置地域/地址、app_id、密钥与 workspace 要求。首次 input.prompt，后续传入服务器保存的 session_id；上游使用 SSE。与旧知识库协议分别实现解析。

先保存脱敏真实响应作为协议样例：普通回答、知识检索、工具调用、结束、业务错误、断流。仅提取对用户公开的最终回答，规划内容和工具原始输出不展示。按实际协议区分增量与累计文本，处理跨 chunk 帧、多行 data、心跳、业务错误；HTTP 200 不作为回答成功的唯一依据。完整结束后才保存成功结果与会话状态。

首版可缓冲上游 SSE 后向网页返回完整答案，减少半截回答被保存的风险。网页实时显示读取原文/生成/失败状态；逐字流式展示后续按需增加。

依据分三类：新闻事实、知识库资料、模型补充背景。新闻参数、日期、进展必须依据原文。知识库不足时允许解释稳定基础概念，明确未取得知识库依据，不编造精确参数或引用。原文没有说明技术难点时，用“这类任务通常涉及的技术挑战”，不声称本次难点已被证实。

引用来源必须来自可信工具/检索结果；服务器验证段落编号和文档标识。回答文字中的“知识库指出”或模型自行列出的链接不作为检索证明。如果发布接口未返回足够的结构化知识来源，应显示依据不足，先解决引用链路，再开放解读自动入库。旧问答无依据拒答逻辑不能直接套在新闻客户端，因为新闻全文本身也是事实依据。

科普解读默认 600–1000 字，含发生了什么、原理、意义、限制和来源；后续回答直接围绕用户问题，不强制每轮重写长文。网页和检索内容为资料，不具有指令权限。

## 6. 网站 API 与会话

以下为拟新增接口，不是现有接口：

| 接口 | 用途 |
|---|---|
| GET /api/news/{id}/agent-status | 是否开放、原文支持状态、已有公开解读 |
| POST /api/news/{id}/conversations | 创建绑定新闻的会话 |
| POST /api/news-agent/messages | 提交会话、问题、request_id；返回任务 ID |
| GET /api/news-agent/jobs/{id} | 查询本人任务，返回阶段/最终答案/依据 |
| DELETE /api/news-agent/conversations/{id} | 清除本人会话 |
| POST /api/news/{id}/explanation-jobs | 请求生成解读草稿，去重并占用额度 |
| GET /api/news/{id}/explanation | 读取当前已发布解读 |

公众客户端只提交本站会话 ID，不提交上游 session_id、模型、app_id、工具密钥或 provider URL。会话绑定访问者、article_id、正文版本、Agent 配置版本；消息接口从会话恢复新闻，不能通过请求任意切换。

同一新闻可保留个人会话，换新闻不沿用同一个上游 session_id。上游会话过期明确重建并恢复经限制的新闻上下文，不盲目重发可能已收费的请求。正文更新时提示新建会话，原版本失效或撤回时停止旧会话使用；历史消息引用固定版本。

匿名身份、请求幂等、同会话单个运行任务、全站并发与日额度参考现有 ai.py。消息、抓取、解读生成分别限额，工具重复调用也受预算约束。浏览器重试同 request_id 查询既有任务；不因网络重试再产生一次收费调用。进程重启将不确定状态标为 interrupted，不自动重复收费任务。

## 7. 持久化设计

复用 news.sqlite3 的 article_id。新闻 Agent 新建独立表，数据库路径均在既有持久卷 /data 中；具体放入 ai.sqlite3 或独立 news-agent.sqlite3 在开发迁移时固定，不能放进容器临时文件系统。建议独立 news-agent.sqlite3 管理本模块任务和缓存，既有全站额度需统一统计。

| 数据 | 主要字段 |
|---|---|
| news_contexts | article_id、版本、原文散列、正文块、完整性、读取状态、抓取/失效时间、使用策略 |
| news_agent_conversations | 本站ID、owner、article_id、正文/配置版本、上游session_id、过期/删除状态 |
| news_agent_jobs/messages | request_id、owner、会话、阶段、答案、引用、用量、错误、时间 |
| news_explanations | 新闻/正文/提示词/模型版本、正文、依据、状态、审核与生成时间 |
| explanation_sync_jobs | 解读版本、目标库/文件/索引任务ID、状态、重试与错误 |

上游 session_id 不公开，按已有主密钥机制保护；密钥沿用管理后台加密存储方式。日志只记录状态、耗时、用量和请求标识，避免原文、会话及凭据泄露。个人会话采用既有保留策略并支持删除。数据库迁移版本化且幂等，默认开关关闭；旧版代码能够忽略新增表。

## 8. 新闻页交互

在已有阅读页增加“科普解读与提问”区域；只有原文链接的新闻也有可达入口。保留新闻列表、原文链接和现有全文展示规则。

首次打开不自动调用模型。用户点击“生成科普解读”或发送问题时才执行；已有公开解读直接展示。状态包括未开放、读取原文、正在解读、完成、读取不完整、来源暂不支持、额度已用尽、失败及会话过期。

展示新闻标题/来源与真实引用；检索不到的背景不伪装成知识库引用。模型输出使用受控 Markdown/纯文本，链接使用已取得且允许展示的地址。关闭阅读页、切换新闻和刷新不能串入旧结果；生成已经发起时应说明离开页面不一定取消上游调用。

## 9. 解读库同步（第二期）

流程：生成个人或后台草稿 → 后台核查事实和引用 → 发布 → 生成 Markdown 文档 → 上传/解析/索引 → 查询任务成功 → 标记可检索。

草稿不得跨用户公开；公共草稿任务去重只复用任务/内容，不泄露所有权、会话或个人提问。日常问答不自动入库。

每篇文档携带 article_id、标题、新闻日期、来源URL、正文版本、解读版本、生成/审核日期、依据与未核实背景标记。解读作为派生材料，检索时保留新闻源，避免拿旧解读互相印证产生循环依据。

采用对应知识库版本 API，不混用旧版 OpenAPI 与新版接口。模型调用 Key 不等于知识库管理 API 凭据，管理凭据采用最小必要权限并在服务器保存。先人工导入少量文档验证召回，再开发同步任务；更新/撤回要追踪旧云端文件并移除索引，支持重试与人工补偿，不重复新增文档。

跨新闻比较需选定/检索相关新闻并回到原文核实；当前新闻会话不能默认为允许读取任意其他文章，比较功能独立扩展可信工具范围。

## 10. 实施阶段与验收

| 阶段 | 工作 | 通过条件 |
|---|---|---|
| A 协议联调 | 应用配置、脱敏SSE样例、引用与会话、MCP传输/鉴权/上下文传递验证 | 有结构化协议样例；能判定结束/失败；明确工具可达路线 |
| B 原文服务 | 缓存、任务、已支持来源及缺全文来源适配 | 完整/部分/失败有明确区分；并发读取同稿不重复抓取；表格不遗漏 |
| C 新闻问答 | 新适配器、会话/任务/额度、新闻页入口 | 已有全文和补读原文均可解读/连续追问；工具日志证明MCP确实调用；切换新闻不串话 |
| D 解读管理 | 草稿/预览/发布/撤回、数据库保存 | 仅发布版本公开；正文变更使解读过期；可恢复和审计 |
| E 知识库同步 | 文档导出、索引任务、更新/撤回、历史检索 | 新版召回成功；旧版撤下；无重复文档；失败可恢复 |

A–C 为首期必交；D–E 为第二期。每阶段报告本地验证、控制台实测、服务器验证各自状态，不能互相替代。

测试覆盖：正文提取含列表表格、中英文、动态/拦截/空页；SSE完成/断流/错误/累计文本；匿名会话隔离、越权与跨新闻工具调用；超时、断网、重复请求、额度、重启；外部网页提示词注入；旧通用问答、新闻分页、阅读、资料下载回归。使用固定样例离线验证，再以少量真实新闻完成云端联调。

内容验收至少选 10 篇不同来源新闻，含全文缺失、知识库覆盖/缺失与原文无法读取样本；检查数字单位、消息日期、计划与结果、引用有效性和背景推断措辞。HTTP 200 或输出一段文字不算验收通过。

## 11. 建议模块与部署

- backend/news_context.py：正文获取及状态；backend/news_context_store.py：缓存/任务。
- backend/news_agent_client.py：DashScope SSE；backend/news_agent.py：API/会话/额度。
- backend/news_mcp.py：鉴权工具层，共用原文服务。
- backend/news_explanations.py：解读版本/发布；backend/explanation_sync.py：第二期云端同步。
- web/news-agent.js、news-agent.css：阅读页问答；修改 news-reader.js 和 index.html 添加入口。
- 私有 admin_web：第二期配置、解读预览与同步状态；tools 与 tests：迁移、联调、发布及回归。

基于既有单应用实例部署，抓取转线程/异步队列避免阻塞 FastAPI；首版以低并发符合现有资源限制。独立开关控制新闻 Agent、原文服务、解读同步。后台任务异常不得影响新闻或通用问答。

上线：备份现有源代码、镜像、配置与持久化数据库 → 幂等迁移 → 发布后端/前端及MCP入口 → 开关关闭验证 → 控制台关联工具并重新发布Agent → 少量真实新闻测试 → 开放入口。该功能涉及后端和迁移，不能沿用仅前端热更新包完成上线。

回退：先关闭新闻Agent及同步任务，恢复上一版镜像和前端；保留新增表与证据，不覆盖回退期间新增新闻数据。MCP密钥可撤销，解读库停止同步或移除出错版本。服务器部署命令在实施完成后按实际配置生成。

## 12. 开发前待核实信息

1. 控制台复制的应用ID、地域/业务空间、完整调用示例和脱敏SSE（不在聊天收集密钥）。
2. 航天知识库所属版本、检索服务关联及结构化引用返回情况。
3. 实际HTTPS域名/反向代理及百炼MCP到服务器的可达性、可信范围上下文传递方式。
4. 实际启用来源、补读优先级、原文AI使用与缓存策略的配置依据。
5. 第二期解读库版本与管理API鉴权、发布审核方式。以上不阻塞先编写原文服务及离线协议测试。
