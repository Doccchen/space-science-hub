# 星知航：资料管理与百炼配置后台实施方案

日期：2026-10-06。状态：方案准备，尚未开发或部署。

## 1. 目标与范围

扩展现有私有管理后台，增加“资料管理”和“AI 设置”两个页面，让管理员通过浏览器维护资料下载地址和现有百炼知识库问答服务配置。

本轮复用现有单管理员登录、过期会话、登录失败锁定、Origin/CSRF 校验，以及独立管理容器。默认继续通过服务器本机端口与 SSH 转发访问，不在公开网页增加后台入口。

本轮包含：

- 资料列表查询、编辑、新增、上下架、排序、修改历史和恢复上一版。
- 资料 PDF 地址更新，支持当前 OSS 来源的完整 HTTPS 地址或对象路径。
- 现有百炼服务启停、API Key 替换、业务空间 ID、知识问答服务 ID、超时及额度配置。
- 配置持久化、生效状态、回退、权限校验、审计和迁移工具。

本轮不接入其他模型厂商、不提供任意 API 地址、不增加大文件上传或在线 PDF 阅读。百炼底层模型、提示词及知识库关联继续在百炼控制台维护；网页后台管理本站调用配置。

## 2. 当前实现与必须解决的问题

| 当前实现 | 相关位置 | 实施要求 |
| --- | --- | --- |
| 独立私有后台，已有身份校验 | backend/admin_app.py、backend/admin_auth.py、admin_web/ | 扩展现有后台并复用鉴权，不在公开服务挂载管理写接口 |
| 资料来自 JSON，启动时载入内存 | content/resources.json、backend/resources.py | 转为持久化目录，保证后台修改可被公开进程读取 |
| 地址由指定 OSS 域名与对象路径生成 | backend/resources.py | 保留来源限制、PDF 路径校验及浏览器直下模式 |
| AI 设置来自环境，启动时创建服务 | backend/ai.py、backend/app.py | 增加数据库配置读取与运行时生效机制 |
| 百炼接口为北京业务空间知识问答协议 | backend/bailian.py | 保持现有协议和依据展示，不增加自由接口地址 |
| app 与 admin 是不同容器，已有共享 /data 卷 | compose.yaml | 通过共享持久化数据同步，不能靠修改 admin 内存影响 app |

## 3. 管理页面与操作流程

### 3.1 资料管理

列表显示封面、书名、分类、文件大小、上架状态、排序、修改时间，支持搜索及状态筛选。

编辑表单包含书名、作者、分类、标签、文件大小、PDF 地址、封面选择、排序和上架状态。沿用现有前台无介绍设计，不增加新的介绍展示。

PDF 地址可粘贴当前允许 OSS 域名下的完整 HTTPS 地址，也可填写 public/ 下对象路径。后端统一解析并保存规范路径，正确处理中文、空格与编码；拒绝非 PDF、其他域名、查询参数、临时签名地址、凭据、端口及路径穿越。首版沿用当前唯一 OSS 来源，增加其他来源需另行调整配置允许列表。

既有资料 ID 不变，地址修改后原 /api/resources/{id}/download 继续有效。新增资料生成唯一 ID，默认下架。优先使用下架代替永久删除。新增资料可先无封面；封面选择来自已有本地封面资源，首版不上传封面。

流程：打开资料 → 编辑 → 本地格式校验与变更摘要 → 保存 → 刷新公开资料页检查。更新书目保留排序及既有元信息，管理员可分别编辑。恢复上一版生成新修订，而非删除历史。

保存成功表示数据已持久化，不代表远端文件实际可下载。另设“检查文件”按钮，仅对已验证的 OSS 地址发起有超时和频率限制的 HEAD 请求，不跟随重定向、不下载整本 PDF。显示可访问性及服务返回的大小；远端不支持 HEAD 时显示“无法自动确认”，不冒充不存在。文件大小不静默改写，由管理员确认。

### 3.2 AI 设置

页面分为服务连接、使用限制、生效状态三个区域。

| 区域 | 可维护内容 |
| --- | --- |
| 服务连接 | AI 开关、替换 API Key、业务空间 ID、知识问答服务 ID |
| 使用限制 | 超时、并发、访客每日次数、IP 每日次数、全站每日次数、每日 Token 预算及每次预留量 |
| 生效状态 | 草稿修订、已保存修订、公开服务已加载修订、最近生效结果、测试结果与时间 |

API Key 输入框默认空白，旁边只显示“已配置/未配置”。留空表示保持原密钥；替换密钥是明确操作。前端不接收原密钥、不自动填入、不缓存到浏览器存储。停用 AI 不要求删除密钥。首版不提供删除密钥操作。

流程：编辑草稿 → 保存并进行本地格式及范围校验 → 可选实际问答测试 → 点击应用 → 查看公开服务生效结果。草稿与当前生效版本分开，未应用的保存不影响访客。

问答测试单独点击，明确“会调用百炼，可能产生费用”，不在保存、加载页面或定时健康检查时自动调用。测试有固定短问题、次数限制、超时和全站预算约束，结果脱敏，记录用量；测试失败不得替换当前可用配置。首版允许不经付费测试应用格式合法的配置，但清楚显示“尚未实际验证”。

数值沿用现有合理范围，校验 Token 预留量与每日预算的关系，不让表单成为绕过费用限制的入口。后台描述明确：本站额度属于调用控制，不是云账单金额硬限额。

## 4. 持久化与配置优先级

新增 /data/site-management.sqlite3，存储资料目录、修订、AI 配置与脱敏审计。与新闻和 AI 会话数据库分开，减少耦合。app 与 admin 共用管理库，但原管理员身份仍通过既有新闻库验证。

建议数据表：

- resource_items：稳定 ID、经现有 Resource 模型校验的目录记录、修订号、修改时间。
- resource_revisions：修改前后可恢复的书目快照、操作人、时间。
- ai_config_versions：不可变配置版本、加密密钥、创建时间、基础验证状态。
- ai_config_state：当前期望生效版本、公开进程确认版本及结果、上报时间。
- management_audit：资料 ID 或配置版本、操作类型、操作者、时间及脱敏变更摘要。
- schema_meta：数据库版本、迁移完成标记。

修改采用事务与乐观版本检查。两个页面同时编辑同一资料/草稿时，后保存者收到冲突提示，重新加载后处理，不静默覆盖。

首次显式迁移导入现有 28 份目录，必须经过完整目录校验、数量/ID/路径对比；不在每次启动时重新导入。资料迁移未完成时继续使用现有目录；完成并启用后数据库成为唯一权威来源，数据库损坏时报告不可用，不静默退回过时 JSON。

AI 配置优先级：已应用的后台配置优先；尚无后台配置时沿用现有环境配置。“停用”也是有效的后台配置，不能因 disabled 回退环境并再次启用。首次采纳环境配置需要显式初始化，不把密钥写入日志、参数输出或报告。

## 5. 密钥与运行时生效

API Key 在管理库中加密保存。采用经过维护的密码库，安装时核对版本并固定依赖；不自行设计加密算法。解密主密钥通过独立服务器文件提供，供 app/admin 只读挂载，不打包到镜像、不提交仓库、不通过后台查看。该文件和数据库备份分别保管；恢复必须同时具备二者。

初次部署生成主密钥并限制文件权限。缺失/错误主密钥时拒绝应用加密配置，不覆盖上一版。历史版本也保持加密；页面、错误信息、请求日志、审计均不得包含 API Key 或主密钥。

资料公开 API 直接读取管理库当前已发布数据，更新后新请求生效，无需重启。现有前台 API 响应格式和 302 下载入口保留；目录规模较小，首版不引入新的目录内存缓存。

AI 公开进程在受控同步机制中读取目标版本，目标为正常情况下 2 秒内加载；启动时立即读取。后台展示“已保存/等待生效/已生效/生效失败”，通过公开进程写回的版本及新鲜心跳判断，不能把保存成功等同生效成功。

必须保持一个长生命周期 AIService，配置/客户端作为请求开始时捕获的不可变快照更新，保留服务级并发计数和额度状态。停用或切换只影响生效后的新请求；已开始回答的请求按原配置完成。

不能直接重新构造现有 AIService：其初始化会处理 pending 请求，可能错误结束正在回答的记录；清理任务也可能继续持有旧实例。实施时拆分一次性启动恢复与日常配置刷新，清理任务统一使用长生命周期服务。

连接配置（密钥、业务空间、服务 ID）变更和停用再启用产生新的会话兼容版本，旧对话提示开启新对话。仅额度或超时变更保留会话。任何配置修改或回退都不重置当天已用次数、Token 或在途预留量，也不通过建立新服务绕过并发上限。回退使用上一版参数创建新的生效修订。

待应用配置有解析/解密错误时保留旧版本，明确上报失败。结构合法但远端认证失败时显示服务错误，支持管理员回退；不静默反复切换配置或自动付费探测。

## 6. 接口与模块组织

管理 API 仅在 backend.admin_app 的独立服务提供，全部使用现有登录与修改校验。建议新增 backend/management_store.py、backend/resource_admin.py、backend/ai_config.py，以及对应 admin_web 页面脚本和样式。

建议接口（路径以私有后台为基准）：

| 接口 | 用途 |
| --- | --- |
| GET /api/resources | 私有资料列表，含下架条目 |
| POST /api/resources | 新增默认下架资料 |
| PATCH /api/resources/{id} | 带修订号修改、上下架、排序 |
| GET /api/resources/{id}/history | 修改历史 |
| POST /api/resources/{id}/restore | 恢复指定历史记录并生成新修订 |
| POST /api/resources/{id}/check | 检查受限 OSS 地址 |
| GET /api/ai-config | 脱敏配置与生效状态 |
| POST /api/ai-config/drafts | 保存校验后的候选版本 |
| POST /api/ai-config/test | 有限、明确触发的真实测试 |
| POST /api/ai-config/apply | 指定候选版本作为目标版本 |
| POST /api/ai-config/restore | 采用上一版参数生成新的目标版本 |

GET 响应不得包含密钥；写入错误采用固定、脱敏信息。公共 /api/resources 和 /api/ai 的既有契约保持兼容。前台仅补充配置变更时的重新开始对话提示，无需重做页面。

## 7. 实施顺序与阶段交付

| 阶段 | 实施内容 | 交付与完成条件 |
| --- | --- | --- |
| 1：基础与迁移 | 管理库、迁移命令、审计、备份与修订冲突处理 | 目录可重复迁移检查且不覆盖修改，原新闻/AI 数据保留 |
| 2：资料管理 | 后台列表表单、写接口、公开目录读取、地址检查和回退 | 更新地址后前台入口即时采用新地址，重启后仍保留 |
| 3：AI 配置 | 加密、草稿/应用/回退、长生命周期服务、状态上报 | 配置可生效且不破坏正在回答的请求或额度 |
| 4：联合验收与部署准备 | 权限、故障与迁移回归；管理页面使用检查；发布说明 | 验收通过，形成代码/管理数据联合备份和回退步骤 |

按上述顺序串行推进，每阶段先完成本地验证。测试使用临时库与模拟百炼响应，不调用收费服务；真实问答验证由管理员明确点击执行。服务器操作继续由用户执行，另准备可审阅发布脚本与部署说明。

## 8. 验收标准

### 资料

1. 未登录、无有效 CSRF 或来源错误的修改请求被拒绝。
2. 首次迁移后，当前 28 份资料的 ID、地址、分类、排序和上架状态正确；重复迁移不会覆盖修改。
3. 修改 PDF 地址后，原下载入口跳转到新地址；搜索、分类、分页及下载保持兼容。
4. 下架资料从前台消失，直接访问其下载入口也不再提供文件；重新上架恢复。
5. 重启 app/admin 或重建镜像后，后台修改仍保留。
6. 外部域名、恶意路径、非法编码、非 PDF、签名参数被拒绝；自动地址检查不跟随跳转。
7. 并发编辑提示冲突；上一版可恢复；检查失败不污染已保存目录。

### AI

1. 公共 API、后台读取、日志、审计、错误及浏览器存储均不泄露密钥。
2. 留空密钥不清除旧值；新密钥不能被读取回显。
3. 草稿保存不影响访客；应用后版本与状态正确，正常同步目标为 2 秒内。
4. 切换、停用、再启用和回退不错误结束正在生成的回答、不重置额度或放大并发。
5. 连接变化后旧对话不能混用新知识库；额度变更保留对话。
6. 缺失主密钥、坏配置、上游鉴权失败、服务离线和过期心跳都有明确状态与恢复路径。
7. 常规保存、查看与健康检查不调用百炼；测试有费用提示、次数与预算限制。
8. 后台明确停用不会回退环境配置再次启用；重启后生效版本不丢失。

### 部署与回退

上线前核对现有私有后台是否已启用，备份新闻库、AI 会话库和新增管理库，并分别保护解密主密钥。SQLite 使用一致性备份，不直接复制处于写入状态的数据库文件。

发布需要同时更新 app/admin 镜像和 Compose 密钥挂载配置，确认两容器看到同一管理库；进行非付费健康检查与用户浏览器验收。

应用内回退通过资料历史/AI 上一版实现。代码回退到旧版时，旧程序不认识管理库：必须先导出当前目录到旧 JSON 格式，并通过受限本机工具恢复旧环境配置，再重启旧镜像。该过程不输出密钥。不得仅回退镜像便宣称后台修改已保留。

## 9. 竞赛演示建议

建议演示“后台更新一个资料地址 → 前台使用新入口”和“后台停用 AI → 前台显示停用 → 重新启用并确认版本”两个闭环。使用测试资料、遮蔽敏感输入，不在录屏中出现服务器密钥或真实 API Key。真实问答测试只在需要展示时执行。

本轮准备只形成方案，不代表后台已开发、上线或经过上述验收。
