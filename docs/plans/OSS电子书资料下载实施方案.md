## 1. 已确认需求与材料

页面显示电子书封面、书名、内容介绍及下载入口。不做在线预览，不嵌入PDF，不接PDF.js，不做全文解析、全文检索或AI在线介绍生成。

用户已将PDF上传OSS并测试下载，采用公共读访问。用户提供的实际示例为：https://space-hub-pub.oss-cn-chengdu.aliyuncs.com/public/numerical-analysis-2nd-edition.pdf 。

已确定PDF地址基准：https://space-hub-pub.oss-cn-chengdu.aliyuncs.com/public/ 。Bucket为space-hub-pub，地域为成都；目录中的上传文件名在核对实际对象后映射到该public/前缀，不使用带临时签名的地址。建议封面对象前缀为public/covers/，该前缀尚未创建/上传或验收。

用户已确认示例可下载。本轮在规划方执行环境尝试只读HEAD时发生传输EOF，未取得响应头、没有下载PDF；不能据此判定文件失效，也不能声称Content-Disposition已核验。实施验收须从可访问的实际环境核对Content-Type、Content-Length与附件下载行为。

本地材料位于E:/storage/oss-public。本次只检查文件清单：31份PDF，合计约2542.5MiB，没有jpg/png/webp等封面图片；有《文件名对照表.csv》，字段为“原始文件名、上传文件名”。中文显示标题以该对照表为基础，OSS对象名称保留已上传的英文文件名。

对照表校验发现部分原始文件名中的英文逗号没有按CSV规则转义，标准CSV读取时有5行列错位（例如上传文件名被误读为作者姓名）。这不是确认PDF缺失：需将每行末尾的上传文件名与实际31份文件逐一核对，再用规范CSV写入器或JSON重建映射。不得直接信任普通Import-Csv结果生成下载地址；原表保持只读，规范化清单另存项目目录并供用户审核。

文件包含航天相关内容及数学、控制、电路、程序设计等专业基础材料。目录和分类按实际内容，不把每本书都标成航天科普读物。31份文件是待整理候选清单，发布清单由用户确认；没有公开分发条件的文件不自动发布。

## 2. 页面设计

沿用现有资料下载导航和浅色风格，替换资料库空状态，其他新闻与Agent页面保持原状。

页面标题“资料下载”，说明“航天与工程学习资料，按需浏览与下载”。搜索框支持书名、作者/编者、关键词；分类及格式筛选按真实清单生成，不预先填充不存在的类别。

主体采用书架网格：桌面三至四列，平板两列，手机一至两列，按实际卡片最小宽度调整。每张书籍卡片包含：

1. 封面缩略图，约2:3展示区，object-fit:contain，保留实际封面，不裁掉标题。
2. 整理后的书名；长书名允许两至三行，详情可看完整标题。
3. 作者/编者、版本或出版信息（有依据才显示）。
4. 两至三行简短介绍、分类、PDF格式与实际文件大小。
5. “内容介绍”和“下载PDF”两个动作，无“在线阅读”按钮。

点击封面、书名或“内容介绍”打开轻量详情面板：完整书名、作者、来源说明、详细介绍、语言、格式、大小和下载按钮。详情面板只是元数据，不加载PDF。

介绍建议卡片60—100字、详情150—250字；不强制为资料不足的文件凑字数。不得编造作者、版本、出版年、章节、学习难度或适用对象。

卡片下载按钮、键盘焦点、弹窗关闭和手机触控明确可用；没有封面时采用带书名的中性占位，并标“暂无封面”，不生成冒充原书的AI封面。

封面图片固定宽高以免布局跳动，首屏外采用lazy loading。不使用自动轮播、大幅背景图或复杂动效。

## 3. 封面与内容介绍：离线准备

源PDF只读，不修改E:/storage/oss-public原文件，也不把2.5GiB的PDF复制到网站仓库、Docker镜像或服务器。

实施Codex先用PDF处理流程在本机读取第一页，生成JPEG或WebP缩略图，长边约600—800像素，目标每张不超过约120KB，实际效果以书名清晰可辨为准。一次性批量处理可串行运行，运行时服务器不渲染PDF。

第一页若为版权页、空白或内页，不自动认定为封面；标记待审核，由用户指定封面页或补图。不得为封面探测读取每本全部内容，也不把整本PDF转换成图片。

封面建议上传同一OSS的public/covers/前缀，英文上传文件名对应稳定的封面名；使用已确定公开域名，并在上传后实测公开读取。可以用版本化文件名避免缓存错图。官网页面从OSS读取缩略图，PDF仍由OSS直接提供。

离线介绍流程：读文件名对照表 → 核对封面/书名页与必要目录或前言 → 草拟介绍 → 用户审核 → 写入目录元数据。可使用模型辅助草稿，但本轮不建设在线摘要服务，审核后的介绍作为静态内容发布。

《文件名对照表.csv》只承担名称映射，不提供未经核对的书籍内容。移除文件扩展名、整理明显文件名噪声需保留原值，作者与版本要从实际材料确认。

## 4. 文件与目录分离

采用“网站提供目录，OSS提供文件”的架构：

浏览者 → FastAPI读取书籍元数据 → 页面显示封面/介绍 → 点击下载 → 浏览器请求OSS PDF。

下载不经FastAPI流式转发，不先fetch整本PDF到浏览器内存再下载，也不通过服务器代理这些大文件。大文件流量由OSS承担，服务器只处理小型JSON与页面请求。

首版目录使用经过审核的content/resources.json，由Git管理元数据，不引入独立数据库迁移或后台管理系统。文件列表少量且低频更新，人工修订清单即可；后续需要网页管理再另行规划。

目录字段：

| 字段 | 说明 |
|---|---|
| id | 稳定资料ID，不能仅用数组序号 |
| title | 审核后的完整显示书名 |
| original_filename | 对照表中的原文件名，保留整理依据 |
| object_key | 已上传PDF的准确OSS对象名，含真实前缀 |
| cover_key | 封面缩略图对象名；未生成可空 |
| description_short / description | 简短介绍与完整介绍 |
| authors / edition / language | 有依据才填写，缺失不猜测 |
| category / tags | 用户确认的目录分类与检索词 |
| format / size_bytes | PDF及本地或OSS核对的实际大小 |
| source_note | 资料来源、发布说明或整理依据 |
| published | 是否进入公开目录，默认未审核不发布 |
| updated_at / display_order | 元数据更新时间与稳定展示顺序 |

公开域名及可选前缀放环境配置，不重复硬编码在所有卡片。对同一路径只编码一次，正确处理空格、中文和特殊字符；保持英文对象名与对照表完全一致。

不保存有时效的控制台签名链接，不提交访问密钥。公共读首版不需要为文件下载接入OSS签名SDK或模型API。若后续改私有访问，单独增加服务端临时签名方案，而不是把过期URL写进清单。

## 5. API与下载行为

- GET /api/resources：仅返回published=true的目录元数据，支持q、category、page、page_size，查询长度和page_size设上限，使用display_order/id稳定排序。首版每页12本，当前28本材料若全部审核发布则分三页；最终总数以审核清单为准。
- GET /api/resources/{id}：返回公开资料详情，未发布或不存在返回404。
- GET /api/resources/{id}/download：校验公开状态及配置的准确OSS域名、对象路径后，302跳转到该书的OSS地址。只接受资料ID，不接受访客传入任意url、bucket或key参数。请求仅生成受控地址，不读取PDF字节。

下载按钮使用正常链接跳转，不用JavaScript请求整本文件。按钮响应不能计作“下载完成”，页面不显示未经证实的下载成功提示，也不将点击次数当作完整下载次数。

要保证“下载”而非浏览器直接打开PDF，应核对OSS对象Content-Type及Content-Disposition。公有对象推荐通过OSS元数据设置attachment与合适的文件名；中文名需要正确编码，不因前端设置download属性就假定跨域下载一定生效。

首版不做下载统计或评论。不存在的对象、失效配置、权限问题需要在验收和发布前检查；不在每次页面加载时逐本远程探测OSS，以免增加请求和延迟。

封面和PDF链接采用HTTPS。普通图片展示和链接下载无需为本轮额外实现PDF读取型CORS功能；若未来使用fetch读取文件，才按实际域名和需要配置OSS CORS。本轮不修改Bucket全局访问权限，公开范围由用户确认后在OSS管理端配置。

## 6. 实施顺序

1. 修复对照表含英文逗号造成的5行解析错位，另存规范化清单；核对31份映射、真实公开链接、PDF对象前缀和允许发布清单；选三本有代表性的PDF试跑。
2. 本机生成三张封面，核对标题、说明、大小和附件下载行为，再为本次OSS清单其余已审核文件生成封面。三份未列出的本地文件保持待确认，不自动纳入批量发布。
3. 整理介绍草稿和目录JSON，用户审核；上传封面到已确认OSS前缀。
4. 实现目录/详情/下载API及页面网格、搜索分类、分页、空/错误/封面缺失状态。新增content目录必须同步Dockerfile与.dockerignore的COPY/允许规则；不能仅在本机可读。
5. 回归现有新闻与筛选功能，构建升级测试服务器，保持原数据库和历史队列。
6. 验收真实PDF下载、封面、元数据、分页与手机界面；完成一个功能后统一提交和git push，由用户执行。

建议目标约1—2个工作日，实际取决于介绍审核、封面页是否可用和OSS公开链接整理。先做三本端到端试跑，避免31份都处理完才发现地址或封面格式错误。

## 7. 验收标准

资料清单核对：31份本地候选映射无遗漏或重名覆盖；本次28份OSS对象逐项对应，三份未列出候选保持待确认，最终发布数量明确。文件真实大小与书名对应，不要求未审核资料全部公开。

页面：封面清晰且不裁掉标题；介绍与实际内容一致；中文书名正确；桌面及手机操作可用；搜索/分类/分页无重复、无遗漏；空结果和缺封面状态合理。

下载：每个已发布对象确认真实存在，首批至少完整下载三个实际文件并核对大小/可打开性；其中覆盖较大PDF与中文显示书名。其余逐项核对对象存在与大小。完整下载通过不能仅由HTTP200或点击事件推断。断链或下架资料不存在无效可用按钮。

资源与边界：页面初始请求只有目录、封面等小资源，不下载PDF；服务器不接收或转发PDF正文；目录和前端不含密钥/签名凭据；没有在线预览、PDF渲染或在线介绍生成服务。

部署：容器中能读取目录清单，重建后目录/封面地址仍正常；新闻模块原有数据、调度与页面不受影响。真实下载由用户在能访问服务器的浏览器测试，测试结果与自动检查分别记录。

交付：代码变更、审核后的元数据、封面清单、OSS配置说明（无密钥）、固定测试结果及资料下载功能验收记录。方案或半成品不单独推送。

## 8. 技术依据

- [阿里云：自定义下载文件名](https://help.aliyun.com/zh/oss/set-the-file-name-for-downloading-an-oss-file)：下载响应可通过Content-Disposition控制。

- [阿里云：预签名链接](https://help.aliyun.com/zh/oss/user-guide/how-to-obtain-the-url-of-a-single-object-or-the-urls-of-multiple-objects)：签名URL有有效期，不适合作为固定公共目录地址。本方案当前采用公共读访问。
