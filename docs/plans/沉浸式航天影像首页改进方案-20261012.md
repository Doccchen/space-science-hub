# 知航 · 沉浸式航天影像首页改进方案

> 2026-10-12。供后续 Codex 读取和执行。本文是实施方案，不代表首页已经开发、验收或部署。
> 当前任务只编写方案。执行者收到明确的实施指令后再修改代码；部署、推送 GitHub 按后续用户指令执行。

## 1. 目标与已确认方向

把新闻页里的图片轮播移为一个独立的首页视图，让访问者先进入航天影像，再进入新闻、知识库问答或资源导航。第一版采用全屏手动画廊，不定时自动轮播。

用户已确认：

- 欢迎动画仅在当前浏览器首次进入时播放。
- 图片展示先采用画廊。
- 文案可以诗意，但必须贴合网站与具体图片的主题。
- 增加可交互的动效，让页面更亮眼、更有沉浸感。
- 不采用本轮调研的 NASA、ESA 图片，转向蓝箭航天官网火箭影像。
- 接受优先使用“整箭与晚霞”作为开场、随后展示点火升空的选材方向。

首版推荐的叙事：**静立于大地 → 点火升空 → 远景中的探索 → 工程细节**。图片承担主体表达，文字和动效帮助观看。

## 2. 实施默认值与范围

以下是便于执行的默认方案，尚不是全部经过用户逐项确认的参数：

| 项目 | 默认方案 |
|---|---|
| 页面结构 | 沿用当前单入口、多个 `main.page` 的结构，新增独立 `#gallery` 首页视图 |
| 默认入口 | 无 hash 的网站访问进入画廊；直接访问其它合法路由进入目标页面 |
| 首图 | 整箭与晚霞 |
| 首版数量 | 5 张，剩余素材作备选 |
| 切换方式 | 按钮、图片索引、左右方向键、触屏横向滑动；无定时切换 |
| 欢迎动画 | 标识与轨道线渐显，再过渡到首图，通常约 1.5–2.5 秒 |
| 视觉方向 | 沿用知航品牌；画廊以图片和深色观看界面为主，其它页面保留现状 |
| 框架 | 优先原生 HTML/CSS/JavaScript 与 Web Animations API，避免为此重写整个网站 |

“独立页面”在首版指独立路由与完整页面视图，不是新闻页里的一个 section。不要把它做成新闻页上方更大的轮播。如果用户后续明确要求独立 HTML 文件或 URL 路径，再调整页面承载方式；本方案先通过 `#gallery` 保留现有深链接体系。

本轮实施包括：画廊、首次欢迎动画、图片交互、素材清单、新闻页移除旧轮播、相关打包与回退准备。

本轮不包括：新闻搜索、资源页图片改造、普通 AI 停用界面重做、后台布局调整、模型或额度变更、增加背景音乐。

## 4. 路由与页面关系

新增画廊视图：`<main id="gallery" class="page">…</main>`。

路由约定：

| 路由 | 含义 | 欢迎动画 |
|---|---|---|
| `/` 或 `/#gallery` | 沉浸式影像首页 | 符合首次条件时播放 |
| `/#news` | 新闻列表 | 不播放 |
| `/#news/article/<id>` | 指定新闻阅读弹窗 | 不播放、不绕回画廊 |
| `/#home` | 当前知识库 AI 问答 | 不播放；保留原有含义 |
| `/assets/resource-navigation.html` | 当前资源导航 | 不播放；保留原入口 |

**不要把已有 `#home` 改成画廊。** 当前它代表 AI 问答，已有链接、脚本和状态逻辑依赖它。

需要同时检查 `studio.js` 与 `news-reader.js` 的无 hash 默认值，避免两个路由入口互相覆盖，使画廊出现后又跳回新闻。确认页面切换仍发送 `pagechange`，已有监听器能识别新的 `gallery` 值。

主站品牌链接返回 `#gallery`；画廊上的新闻、AI 问答和资源导航入口始终可见、可操作。独立资源页的品牌与返回链接按同一导航约定同步核对。

新闻页移除旧 `.space-cover` 展示区域及自动轮播初始化，让新闻标题、筛选和列表自然接续。新闻页的现有列表、分页、筛选、摘要与阅读弹窗不重新设计。

## 6. 首页构图与文案

画面占据主要可视区域，避免在图片上堆叠大段介绍、指标或卡片。

- 顶部：知航品牌与新闻、AI 问答、资源导航入口。
- 主体：全屏图片；标题置于不遮挡箭体和喷焰的区域。
- 底部：当前图片序号、影像索引、上一张 / 下一张、来源入口及“探索影像”。
- 完整图片观看模式：展示完整画面，允许留边，不强制裁掉箭头、着陆腿或发射设施。

正文页延续现有米白、深蓝、橙色配色。画廊的导航可采用适合当前图片的明暗版本，必要时使用局部轻遮罩保证对比度，不把所有照片统一压暗。

首版文案建议如下，实施时可微调，但不能虚构任务事实：

| 图片 | 标题建议 | 内容落点 |
|---|---|---|
| 整箭与晚霞 | 把遥远的想象，立在大地之上。 | 火箭、发射工位、晚霞 |
| 点火升空近景 | 点燃此刻，向更远处出发。 | 点火与升空 |
| 试验箭与荒漠 | 在辽阔天地间，寻找新的高度。 | 荒漠、试验箭、空间尺度 |
| 晨昏工位 | 出发之前，天地已经铺开。 | 工位与天空，不断言具体拍摄时刻 |
| 喷焰与箭底结构 | 远行的力量，藏在每一处细节。 | 喷焰、结构与工程 |

不写“首次成功”“世界第一”“某任务凯旋”等未经这张图片来源确认的文字。知航保持自身品牌，不复制蓝箭官网标识作为本站 Logo，不暗示双方合作或官方背书。

## 7. 欢迎动画与首次记录

状态流程：

```text
解析目标路由
  ├─ 新闻 / AI / 新闻深链接 → 直接进入目标
  └─ 画廊
      ├─ 已看过 / 减少运动 / 存储不可用 → 直接进入可操作的画廊
      └─ 首次 → 欢迎动画与首图加载并行
                    ├─ 播放完成或用户跳过 → 进入画廊，记录已看过
                    └─ 图片失败 / 超时 → 显示可操作的降级画廊与重试
```

- 使用 `localStorage` 保存当前浏览器的首次记录，例如 `zhihang.gallery.welcome.seen`；读写都使用 `try/catch`。
- 首次记录不随普通素材或样式更新更换 key，避免每次发布都重播。
- 只有完成欢迎过程或明确跳过时记录，不在刚开始播放时提前记录。
- 存储不可用时跳过欢迎动画，避免每次刷新都重复播放。
- 同浏览器其它标签完成播放后，尚未开始的标签可通过 `storage` 事件跳过；不强行打断正在观看的交互。
- 清除网站数据后重新视为首次，这是浏览器本地记录的正常边界。
- 提供“跳过”和可选的“重看欢迎动画”；重看是用户主动操作，不清除首次记录。

欢迎过程：品牌标识渐显 → 简洁轨道线勾勒 → 首图显露。图片解码与动画并行，不播放固定倒计时，不等所有图片下载完才进入页面。

“跳过”立即解除动画阻挡。首图未准备好时仍显示画廊导航和加载状态；约 8 秒仍未成功则提供重试与进入新闻入口。任何资源失败都不能让欢迎遮罩永久挡住网站。

欢迎层只有播放期间接收交互，结束后从交互与无障碍树中移除。跳过可用键盘操作，不夺走新闻深链接的焦点，不自动播放声音。

## 8. 互动动效

参数是起始调校范围，以本地观感、稳定性与可用性为准。

| 互动 | 实现建议 | 边界 |
|---|---|---|
| 鼠标移动景深 | 图片轻微位移约 6–12px，文字幅度更小；适度缩放留出移动余量 | 仅精细指针设备；不遮挡主体，不使图片边缘露空 |
| 手动切换 | 450–700ms 交叉显露；标题延后约 80–150ms 跟进 | 新图解码完成再切换，失败时保留当前图；重复操作不能叠加多个动画 |
| 图片索引悬停 / 聚焦 | 展开缩略图和画面名称，明确标识当前项 | 键盘聚焦有同等信息；手机通过点按访问，不依赖 hover |
| 导航悬停 | 下划线延展、文字轻微位移 | 控件点击区域稳定，不跳位，不使用吸附效果妨碍操作 |
| 探索影像 | 隐去主标题与主要导航，保留退出、来源和切图控制；点击放大按钮观察细节 | 不是默认隐藏导航；`Escape` 可退出；放大时拖动只平移图片 |
| 手机手势 | 普通画廊横向滑动切图，纵向手势不劫持页面滚动 | 设定最小横向位移；区分切图、点击与放大平移 |

动画统一以 `transform` 和 `opacity` 为主，最多维护一个指针移动 `requestAnimationFrame`。页面隐藏、离开画廊或进入减少运动模式时取消动画与帧循环。

暂不加入：粒子雨、密集星点跟随、强烈抖动、滚轮劫持、必须按顺序看完的动画、默认全屏音效、自动切换图片。

减少运动模式下，跳过欢迎动画、鼠标景深、位移转场和持续运动；保留静态画廊、按钮、索引及正常导航。CSS 与 JavaScript 两侧都要处理运行期间偏好改变。

## 9. 图片加载与性能

- 原始图片用于留档，不直接把 3–7MB 原图全部作为首屏资源加载。
- 生成适合展示的桌面与移动尺寸，按 `srcset` / `sizes` 或等价方式选择；保留 JPEG 回退。
- 初始只优先加载首图；首图成功后加载邻近图片，索引缩略图用独立小文件。
- 首图使用明确尺寸和高优先级加载；记录解码成功后再揭示，避免闪白和布局跳动。
- 首版目标：普通桌面首图尽量控制在 300–700KB，移动首图尽量在 150–350KB；以细节质量为前提，超过目标时说明原因。
- 展示版不补绘天空、箭体或喷焰，不将生成式增清结果当作原始影像。
- 不用照片的远程热链接作为正式站点依赖，部署选定的正式文件。
- 快速切换用请求编号或取消机制丢弃过期结果，避免出现“图片是 A，标题是 B”。
- 主页面继续使用 base / components / pages 三份 CSS 入口；修改源文件后执行构建，不重新加入大量直接覆盖链接。

## 11. 实施顺序与交付

1. 核对当前代码与线上基线，保存现状截图和此次受保护的功能清单。
2. 确认选定图片可访问、SHA256 与原图清单一致；记录授权待核状态。
3. 先做静态画廊与路由：首图、文案、切换控件、出处、三个功能入口；确认新闻页旧封面已迁出。

## 12. 验收条件

### 首次与加载

- 新浏览器记录访问默认入口：出现欢迎动画，然后进入画廊。
- 跳过欢迎后刷新、关闭重开：不自动重播。
- 存储读写失败、减少运动：仍可直接进入并操作画廊。
- 首图失败、网络慢或动画异常：导航可用，有重试与新闻入口，无无限遮罩。
- 未看过欢迎的浏览器直接访问新闻、AI 或新闻深链接：进入指定功能，不播放欢迎、不改写为首页。

### 画廊与互动

- 没有定时切图；按钮、索引、键盘和手机滑动能手动切图。
- 快速连续切换时，图片、标题、署名和当前索引始终对应。
- 正常模式保留导航，图片观看模式有明确退出，来源入口仍可访问。
- 缩略图信息不仅依靠 hover，所有控件有可见焦点和可访问名称。
- 桌面、窄屏裁切不隐藏关键箭体与喷焰；完整图模式能看全图。
- 离开画廊后，没有持续动画帧、自动计时器或残留监听器影响其它页面。

### 既有功能回归

- 新闻类别、来源筛选、刷新、分页和新闻正文阅读正常。
- 新闻阅读双栏、关闭、返回、深链接与焦点恢复保留。
- 新闻科普入口仍反映后台开关，默认开关与请求准入不被画廊代码改变。
- 普通 AI 问答、历史会话和当前 `#home` 路由不受影响。
- 资源导航入口与独立页面正常，既有后台、凭据、额度和数据不改。
- 样式构建一致性、相关 JavaScript 语法、现有前端检查及发布包校验通过。

验证优先使用本地固定样例。布局、导航与开关检查不得自动调用收费模型。用户要求浏览器验收或准备发布时，再执行相应浏览器检查并保存真实截图；不能把离线模拟结果称为线上验收。
