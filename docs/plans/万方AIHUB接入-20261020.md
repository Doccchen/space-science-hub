## 接口依据

- 文档：https://github.com/wanfangdata/wfdata-open-skills
- 参考：https://github.com/wanfangdata/wfdata-open-skills/blob/master/skills/wfdata-search/references/api-catalog.md
- 认证头：`X-App-Key`；检索接口：`/openwanfang/getQuery`。
- 文档所列 HTTP 地址之外，已独立探测 `https://api.wfdata.com/openwanfang/getQuery`，不携带 Key 返回 401，确认 HTTPS 可达且无重定向。实现固定使用 HTTPS，不跟随重定向。
- 本版先查询 `OpenPeriodical` 期刊题录，获取 Id、Title、Creator、PublishYear、PeriodicalTitle、Abstract、DOI、Type。不下载全文；HasFulltext 不会被误标为开放获取。
- 文档返回结构按 `documents[].fields` 适配。真实账号可能返回业务错误或不同封装，需认证验收后再确认最终字段映射；不把模拟测试当作实际调用成功。

## 配置

在项目目录运行：

```powershell
.\.venv\Scripts\python.exe tools\configure_wanfang.py --check
```

在隐藏输入提示中粘贴 APP_KEY，配置工具写入已被 Git 忽略的 `.env.reader`，变量名 `READER_WANFANG_API_KEY`。`--check` 会向万方官方 HTTPS 地址执行一次「栅格舵」题录检索，可能消耗账号额度；仅输出成功/失败与记录数量，不输出 Key 或上游响应正文。保留其他已有模型配置。未设置 Key 时仍仅使用原四个来源。

本地重启检索服务后生效；生产容器必须显式添加该环境变量并按部署流程更新，不能仅修改宿主机文件就声称上线。平台订阅的数据展示及保存范围需在账号中确认。

## 数据流程

- 主题提取同时保留英文 query 和中文 query_zh，中文来自已确认的技术名称，不额外推测技术路线。
- Search API 新增可选 query_zh；万方使用 query_zh（为空时用 query），原四源继续使用 query。
- 研究助手按服务配置显示可编辑的「万方中文检索词」字段，并标注本次两套检索词。
- 来源失败独立处理，不影响其他来源；不将认证错误、业务错误误报为零命中。
- DOI 优先去重，保留全部来源；沿用现有来源缓存与请求节流。
