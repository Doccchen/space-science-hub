# 航天知识库科普AI实施方案

2026-10-06最新范围：用户已在百炼创建应用并关联知识库，控制台可问答；网页改为用户直接提问，不选择新闻。当前实施以[百炼知识库科普问答网页接入方案](百炼知识库科普问答网页接入实施方案.md)为准。下文新闻关联与本地向量路线保留为此前规划，不作为本阶段实施要求。

日期：2026-10-05。范围：用户浏览一篇航天新闻后，针对不理解的概念向AI提问；国内模型基于专属知识库科普，并用当前新闻的已提供材料理解语境。首版为新闻关联科普问答，不把双版本材料解读或独立全领域聊天列为必做项。

本文为供实施Codex执行的方案，不修改应用代码、不创建付费云资源、不提供凭据、不提交或推送Git。功能完成并验收后由用户统一提交与git push。

前置更新：用户已选择先改造新闻阅读页，采用[正文/图片许可分层方案](新闻阅读页与许可分层实施方案.md)。AI需兼容许可明确的本站正文和导读/节选两种范围，不假设每条新闻都有全文；正文可用且允许模型处理时用其版本化内容，其余按有限材料回答。

2026-10-06展示策略更新：政府来源经正文许可核对后提供本站全文，其他机构和企业仅标题＋原文链接。AI须按source_reading_policy和实际reading_mode组装：full_text且允许模型处理时取正文；link_only只取标题/来源等元数据，不读隐藏旧摘要或宣称已读原站全文。对link_only仍可基于知识库解释用户提出的概念，但不能判断未提供的事件细节。本条优先于此前节选模式设想；当前新闻改造阶段尚不实施AI。

## 1. 首版目标

用户阅读本站新闻，遇到术语、原理或背景不理解，点击“向AI提问”，系统保留当前新闻语境并检索已审核知识库，输出简明解释、必要术语说明及可核对依据。证据不足时明确“当前新闻节选和知识库资料不足，无法据此回答”，不编造参数，也不把本系统缺失说成所有公开资料都不存在。

典型使用：用户看到新闻中的“可重复使用”“载荷”“太阳同步轨道”“交会对接”等词语，询问它是什么意思、有什么作用、与类似概念有什么区别。

概念解释与新闻事实分别处理：例如“可重复使用火箭是什么意思”可由知识库解释；“这次火箭是否回收成功、具体参数是多少”必须由当前已提供新闻材料支持。知识库中的一般技术资料不能自动证明某次任务采用了某方案或取得某结果。

首版为一个受控问答流程，不做模型训练或微调。专属知识库是资料与检索索引，不是把资料塞进一个超长提示词，更不是要求模型凭自身记忆回答。

## 2. 推荐技术路线

推荐默认：阿里云百炼通义千问文本API＋text-embedding-v4向量API＋项目自有轻量知识库索引＋现有FastAPI。

模型优先比较千问Flash与Plus档，选一个通过科普问答评测的主模型；具体模型ID、API地域、非思考/思考模式、结构化输出支持、上下文与价格，以用户账号可调用型号和官方说明实测后锁定。不要只因名字更大或免费就选型。模型推理和文本向量化都通过云API，不在2核2G服务器部署模型。

DeepSeek或GLM可作为后续替换候选；首版不同时接多个平台，不宣称OpenAI兼容就能零改动切换所有参数。提供LLMClient与EmbeddingClient等小型适配接口，API差异由适配层处理。

知识库默认由项目维护：审核后的分段资料存SQLite或版本化JSON，向量存float32文件，使用NumPy完成小规模相似度检索；关键词别名/主题标签作为补充。暂不部署Dify、Milvus、Elasticsearch、独立模型、OCR或重型解析队列。

例如5000片段×1024维×4字节的纯向量约19.5MiB，这是向量本身的理论大小，不含程序与元数据；仍须实测进程内存与并发。text-embedding-v4官方支持可选维度，若采用1024维，应在导入和查询时显式一致。

另一条可选路线是百炼托管知识库。它能减少解析/索引工作，但应先验证账号权限、计费、引用片段与位置是否可返回，以及资料上传条件。当前不将其作为强制前置；若轻量本地检索效果无法满足评测，再评估切换。原始资料及来源索引应保留可导出副本，避免只有云端知识库ID。

## 3. 知识库选材与规模

首版先从当前新闻中梳理高频术语，再建设20—30份短小、可审核的基础材料，覆盖约40—60个新闻阅读常见问题，不以导入文件数量当效果指标。优先覆盖可重复使用、入轨、载荷、轨道类型、交会对接、空间站、月球探测等实际阅读主题，而不是先构建泛化百科库。

主题建议：

| 主题 | 内容 |
|---|---|
| 航天基础 | 自转、公转、重力、轨道、速度等基础概念 |
| 火箭与推进 | 民用航天的原理性介绍与基本术语 |
| 卫星与空间站 | 分类、用途、失重、通信与生活环境 |
| 月球与深空探测 | 月球现象、探测方式、任务基本概念 |
| 阅读航天新闻 | “计划/预计/完成”、试验与正式任务等表述区别 |

材料优先官方科普页面、官方FAQ、公开术语说明和经过人工核对的概念卡片；可使用国家航天局、中国载人航天、NASA、ESA等原始公开来源，英文材料需保留原文依据并核对中文转述。

不自动将资料下载区28份PDF全部导入。它们含专业基础教材，部分体积大、公式与扫描结构复杂，且不等于适合普通读者的知识库。选定的PDF只离线提取相关章节，核对公式、数字、单位与页码后发布。文件下载、知识库引用和向模型API发送片段的使用范围分别确认。

新闻数据库不自动全部入知识库。当前选中新闻的标题、发布时间、来源性质、摘要/正文节选作为本轮语境与有限新闻证据；知识库提供稳定的概念/原理依据。两者分别标注，企业自述、计划和时效性条件保留，不能将新闻与基础知识混成一个无来源答案。

现有页面摘要或正文节选不是完整原文。首版不实时抓取用户提供URL，不增加全文采集；界面和回答均不得声称读过完整报道。节选缺少细节时可解释一般概念，但必须说明无法据此判断这次具体任务。完整原文接入若确有必要再作为单独任务规划。

## 4. 资料加工与发布

离线流程：选材 → 记录来源与范围 → 提取正文 → 按标题/概念分段 → 人工核对 → 调用向量API → 生成版本化索引 → 固定问题试检索 → 发布服务器。

段落初始目标约300—600中文字符，按语义调整。定义、条件、公式/单位应一起保留，不机械在固定长度截断。重叠量按样本测试，不反复复制整章造成大量冗余引用。

每份文档至少记录doc_id、标题、来源URL或文件ID、发布方、发布时间/版本、获取时间、语言、主题、使用说明、审核状态与内容哈希。每段记录chunk_id、文档ID、章节/段落或PDF页码、原文片段、别名/标签、有效范围及向量模型/维度。

知识库发布manifest记录kb_version、索引哈希、embedding模型ID、维度和片段集合。查询必须使用同一embedding设置；换模型不能继续使用旧向量。不能只按文件名替换内容却复用旧引用ID。

原始PDF、整站镜像、未审核材料与大体积工作产物不进入应用镜像。索引导入和重建不在Web启动时执行，不与新闻采集共享长时间写锁。服务器部署已整理索引，支持原子切换及回退上一版本。

## 5. 在线问答流程

问题校验 → 根据article_id读取当前新闻快照 → 识别问题中的术语、指代与是否需要澄清 → 将问题与必要新闻主题组成检索条件 → 关键词/语义检索知识库 → 分开组装新闻节选与知识库证据 → 国内模型生成结构化回答 → 服务端核对 → 展示答案与两类依据。

后端按article_id从数据库读取新闻，不信任前端传来的标题、来源链接或正文。快照包含原始URL、发布时间、发布方/性质、当前节选及content_hash；若新闻已不存在或ID无效，提示重新选择新闻。即使客户端提交“忽略上下文”等文本，也不能替换服务端新闻身份。

“这个轨道”“它为什么这样”等指代结合当前新闻与有限历史解析；存在多种理解时先追问。用户选词作为提问内容，不自动成为新闻原文证据；若选词不在本站节选中，仍可解释知识库已有的概念，但不冒充当前新闻包含该表述。

初始检索最多约8个候选，整理4—6个相关片段送入模型，具体按样本评测调整。分数阈值要用“能回答/不能回答”案例标定，不用任意固定相似度或前三条检索结果当充分证据。可用关键词主题匹配补充召回，不能把默认SQLite中文FTS当作已解决中文分词。

用户请求不赋予联网、任意文件读取、代码执行或自动新增知识来源的能力。首版无浏览器搜索工具、无自主执行Shell、无用户实时文件上传。

连续追问最多保留最近3—5轮或明确的短上下文，每轮重新检索。同一轮对话绑定一篇新闻；切换新闻时新建/清空对话，不能把前一篇事实带入下一篇。历史AI答案不当作证据来源，不能把上一轮错误滚入知识库。历史窗口长度与输出长度有上限，服务端重新校验文章身份。

## 6. 输出与事实约束

输出建议包含：直接解释、与当前新闻的有限联系、术语说明（需要时）、有限类比（需要时）、资料依据、限制/待确认项。默认约300—600中文字，可按问题调整，不以凑长文为目标。一般原理有依据而本次任务信息缺失时，只回答原理并保留任务限制，不为了“联系新闻”强行推断。

生成结果内部按answer_segments、citations、limitations及answered/needs_clarification/insufficient_evidence等状态组织。关键事实片段附上本次检索已有的chunk_id；来源标题、原文URL和位置由服务端生成，不让模型自行构造链接、作者或页码。

引用分为news_excerpt与knowledge_chunk：事件信息引用当前新闻快照，概念解释引用知识库段落。新闻引用位置只能标为“本站展示节选”，不能生成未取得的原文第X段/页码。证据ID使用独立命名空间并绑定新闻快照/知识库版本，避免混淆。

至少校验：结构格式、引用ID属于当前检索集合、引用位置存在、数字与单位对应、对象与时间限定词未被改写。数字仅在上下文出现不代表支持同一个结论；关键数值要绑定证据与对象。类比标注用途与边界，不作为科学事实或原文引用。

本阶段不承诺杜绝幻觉。低温度、模型自检或另一个模型复核只能辅助，不能替代证据核对和人工评测。检查失败可有一次有预算的修复尝试，仍失败则不发布未经核验的答案，显示无法可靠回答。

模糊问题先追问；资料冲突展示差异与适用范围，不选“更晚”就自动判正确；找不到依据返回“当前知识库资料不足”。API超时显示服务暂不可用，不伪装成知识库没有资料。

文档和用户输入都作为资料/请求，不执行其中修改系统规则的指令。未经验证的链接或HTML不进入回答；前端采用安全文本/受控Markdown渲染。

首版先发送真实“检索/整理”状态，回答正文在结构与引用检查后一次展示；不先流式输出尚未校验的内容。后续确需逐段显示再制定每段核验方案。

## 7. 页面与接口

在新闻详情增加“向AI提问”，可在新闻卡片补充同一入口。点击后进入现有科普Agent栏目，保持简洁单栏。顶部显示正在解读的新闻标题、来源和“仅使用本站节选”说明，并提供返回新闻入口。

提供2—3个与本新闻术语及知识库实际覆盖相符的推荐问题、输入框、发送/取消、清空对话及清楚状态。推荐问题可由已审核术语别名与模板匹配生成，不在用户每次打开新闻时调用模型；用户真正提问才发起收费请求。

没有选中新闻而从导航进入Agent时，提示“先选择一篇新闻”，可显示新闻选择入口或保留上一篇仍有效的新闻；不默认带入固定示例材料。选中术语提问为可选增强，首版先支持手动输入。

回答下方显示可展开的依据卡片：材料标题、发布方、章节或页码、有限原文片段和原始链接。资料片段查看不是PDF在线预览，不加载整本电子书。知识库与资料下载分类可保持独立。

页面说明知识库范围与更新版本，不伪装成全网最新航天事实。无依据、模型不可用、达到使用上限、知识库维护和空输入分别处理。

API建议：POST /api/ai/ask接受article_id、question与有限同新闻历史，可选selected_text仅作为提问辅助；GET /api/ai/status返回启用状态、知识库版本和主题范围。响应携带article_id、新闻content_hash、kb_version、回答状态和来源类型。客户端不提交任意系统提示词、模型ID、正文替换或可执行工具定义。服务端重组全部调用。

## 8. 运行与费用

在现有FastAPI增加受控模块，维持单worker，初始同时进行AI请求最多2个；新闻采集与资料目录继续独立可用。输入长度、历史轮次、证据长度、最大输出token及请求总超时均设上限。

请求限流初始建议每IP每分钟3次、每IP每天30次、全站每日总额度可配置，评测后调整。仅信任真实网络连接或已配置可信反向代理，不用访客提供的X-Forwarded-For绕过限流。全站额度和用量持久化，重启不能无限重置预算。

缓存键包括article_id、新闻content_hash、规范化问题、有效同新闻对话条件、kb_version、模型ID和提示模板版本。否定、时间、新闻和主体不同的相似问题不可直接共用答案。新闻节选更新或知识库更新后旧缓存失效。失败响应不缓存为正常知识结论。

凭据只放服务器环境配置，不进浏览器、Git、知识库或日志；模型和embedding平台权限与地域需实测。不得把下载Bucket中的所有文件自动发送给云服务。

费用分别记录首次资料embedding、每次问题embedding、生成输入/输出、修复尝试及重试。按官方账号当前报价计算，不声称永久免费。例如每次生成实际3000输入/800输出token，1000次对应300万输入/80万输出token，另计问题向量化与失败重试；缓存命中率需实际测量，不预设100%。

规划起始设少量每日额度，用完提示稍后再试，不自动切高价模型。模型性能用知识库实际样本、用户阅读效果与时延选型，不以供应商宣传代替评测。

## 9. 实施阶段与完成节点

| 阶段 | 任务与交付 |
|---|---|
| A：准备与验证 | 确认模型平台/可用ID与地域；从阿里云服务器实测模型和embedding；选实际新闻梳理术语，审核首批资料与40个新闻关联固定问题 |
| B：知识库检索 | 本机生成索引、来源定位与版本；验证不同表达能召回证据，无关问题不被强行匹配 |
| C：真实问答 | 完成检索、结构化回答、引用校验、缺失/冲突/澄清、限流及异常处理 |
| D：页面与部署 | 接通新闻→AI入口，替换固定示例，显示文章身份、依据类型与版本；测试服务器更新，验证旧新闻、资料下载仍正常 |
| E：验收与提交 | 模型实际评测、读者试用、预算与资源检查；验收通过后用户提交与git push |

建议目标4—6个工作日，不包含开通账号、权限等待及大规模资料整理。优先用10份短材料跑通检索与真实问答，再扩到完整首版范围；不等全部教材处理完成才调接口。

## 10. 验收标准

固定40个问题建议分为20个有明确答案、5个知识库缺失、5个模糊条件、5个冲突/时效、5个指令注入或诱导编造。原文支持和预期行为由人工建立，不只用另一个模型打分。

问题集来自实际新闻阅读，至少覆盖相同术语在不同新闻中的解释、仅有概念依据但缺少本次任务细节、节选未提供具体参数、“计划”不得改成“已完成”、切换新闻清空上下文，以及过期/无效article_id。分别评估知识科普的正确性与新闻关联的忠实性，不能把概念答对当成事件推断正确。

有答案样本检索召回目标至少90%，回答正确与充分支持率目标至少90%；引用ID有效率必须100%。有引用不等于引用支持结论，语义支持单独核对。任何重大参数编造、无依据的因果或严重误读都需修复或限制回答范围后再通过。

缺失类不得生成肯定数值；模糊类必要时追问；冲突类保持限定；恶意文档/问题不能触发工具或改变来源权限。接口超时、限流、格式异常、索引损坏/不匹配、取消请求与重启分别有测试。知识库不可用不影响新闻及资料下载。

邀请3—5名普通读者检查解释是否易懂，另由熟悉航天知识的人员抽查事实。样本量与结果如实报告，不用“AI有依据”替代理解效果。

实测中位与较慢请求时延、运行峰值内存、两请求并发、模型token用量和限流效果；初始期望大多数典型问题30秒内完成，不在未测试前承诺性能。确认索引重建和版本回退不会丢失已有新闻及资料。

交付：知识库来源/版本清单、离线构建流程、检索与模型适配实现、固定评测报告、服务器验收、读者反馈和未解决清单。不以能聊天或能返回JSON就宣布验收完成。

用户需要确定一个国内模型平台并在本地/服务器配置凭据；规划默认优先百炼千问，并通过样本比较Flash/Plus。首批知识库材料围绕实际新闻术语及使用范围审核，现有电子书下载不等于自动批准整本入库。本阶段入口已明确为新闻关联科普问答，不再要求双版本解读或独立泛化聊天。
