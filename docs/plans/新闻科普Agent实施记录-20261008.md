# 新闻科普 Agent 实施记录

2026-10-08。对应《新闻科普Agent开发方案-20261008.md》。**当前为首期本地实现及离线验证，不是 A–C 完整验收通过，不是已上线。** 方案起草时“仅编写文档”的限制由用户本轮“按方案开展工作”更新为开始实施；没有执行部署或收费调用。

## 已落地

- 独立 `NewsAgentClient` 调用 `/api/v1/apps/{app_id}/completion`，北京地域；配置使用用户复制的应用 ID `e366df4514cb4606b95821b9d03c387e`、业务空间 `llm-ep9bqc9mnw50k8e0`。旧知识问答协议保持独立。
- 按官方应用接口实现 SSE 增量/累计、跨 chunk 行拼接、多行 data、心跳、业务错误、结束和断流判定。只读取 `output.text`；忽略 thoughts 与未知 choices；完整 stop 且非空答案和 session 后才保存成功。结构化知识引用在实测核验前标为 unverified。
- 原文服务从数据库新闻 ID 恢复链接，复用固定 Publisher 的域名、DNS、robots、重定向与预算检查；不接受任意 URL。不修改正文公共展示策略，也不把 `permissions.ai_context.pending` 改成 granted。
- 来源登记覆盖所有本站来源；NASA、国家航天局、中国载人航天、中科宇航、蓝箭航天复用严格正文解析器。ESA 和其他来源明确 unsupported，后续按来源样例适配。静态 HTML 以外暂不支持。
- 缓存按新闻记录/来源策略版本索引；正文块散列形成独立内容版本。成功缓存 6 小时，失败冷却 120 秒；到期由每分钟清理及请求清理移除。同篇读取去重，后台最多 4 个读取任务；调用方 25 秒超时返回 pending，保留有界 worker。特定 DNS 调用仍依赖操作系统完成，不通过超时重复排队。
- 列表、表格和稳定块编号保留；严格结构检查失败标 partial；超过 80 KB / 250 块标 unsupported，不截断后声称已读全文。首版遇 partial 不调用模型。
- 网站接口实现 status、创建/恢复/删除会话、提交消息/解读任务、查询任务。会话绑定 owner、新闻记录版本、正文版本和 Agent 配置版本；后续只由服务器传 session。上游 session 使用既有 `AI_MASTER_KEY_FILE` 的 Fernet 主密钥加密。
- 新闻模型请求计入既有 `ai.sqlite3.requests` 全站、访客、IP、分钟和 token 额度，共用并发。任务 ID 对 owner/request_id 确定性生成；跨数据库提交不确定时也不会重发已有额度预留。重启标 interrupted，不自动重试。
- 新闻任务、私有消息/草稿和正文缓存位于独立持久库 `/data/news-agent.sqlite3`，schema v1，幂等创建。个人会话默认保留 24 小时；过期删除正文答案、问题与解读草稿。额度审计保留既有 30 天策略。删除接口在新闻撤回/过期后仍可使用；迟到回答只记用量，不恢复已删除内容。
- 官方 `mcp==1.30.0` SDK Streamable HTTP，入口 `/api/news-mcp/mcp`。静态服务 Bearer 密钥 + 独立的加密短效 `X-News-Context`；令牌绑定任务、文章、记录版本和到期时间；只允许正在 generating 的任务，每任务最多 3 次调用。无上下文或跨新闻调用返回 blocked。
- MCP 模式只有在开关、上下文转发核验标志、服务密钥和插件 ID 均齐备后才能启动；保存回答前要求服务端完整读取日志与当前版本匹配。`input.biz_params.user_defined_tokens` 是待本应用联调的插件令牌候选映射，不能据官方通用示例宣称 Agent 2.0 已支持本头部转发。
- 新闻列表增加入口；link_only 也能进入阅读器。页面首次打开不调用模型；提交后查询任务，刷新恢复会话。答案以纯文本显示，不执行模型 HTML，也不使用模型提供的网址。仅将服务器验证的块 ID 展示为正文引用。
- 旧 `/api/ai` 路径匿名 Cookie 在首次新闻提交前通过 `/api/ai/visitor` 原值迁移到 `/api`；保留原 owner，避免旧问答会话失效。跨站迁移请求拒绝，Cookie 不返回到 JSON。
- “生成科普解读”结果写入个人 draft；公开解读接口当前始终为空，不跨用户复用私有草稿。

## 配置与联调路线

`.env.example` 和 Compose 已登记独立开关，默认 `NEWS_AGENT_ENABLED=0`、`NEWS_CONTEXT_ENABLED=0`、`NEWS_MCP_ENABLED=0`。数据库位于现有命名卷。`NEWS_AGENT_API_KEY` 是新闻应用专用服务器环境变量，本轮未配置；不要求在聊天中提供 Key。新闻配置后台尚未增加，首版通过受控服务器环境配置；Key 不写入源码、数据库明文或浏览器。独立管理后台加密 Key 编辑属于后续配置工作。

1. 在服务器受控配置中设置 `NEWS_AGENT_API_KEY`，检查既有 `AI_MASTER_KEY_FILE` 挂载有效；保持所有公开开关关闭。不要在聊天或日志打印密钥。
2. 运行 `python -m tools.probe_news_agent`，只报告配置是否齐备，不调用模型。显式收费联调才使用 `python -m tools.probe_news_agent --call --follow-up --output artifacts/news-agent-protocol/application.json`；最多两次调用，错误不重试，输出仅本地脱敏帧。探针不修改云端应用，也不能替代新闻/MCP验收。
3. 检查真实 `output.text/session_id/finish_reason/doc_references/usage`；追加普通回答、知识检索、工具调用、业务错误与断流的真实脱敏样例。核对是否需调整增量模式及 workspace 头。
4. 在隔离环境开启原文与新闻开关，先验证后端传正文模式的连续问答。未配置 Key 或主密钥时 fail closed，旧网站仍能工作。
5. 提供实际 HTTPS 入口，反向代理仅转发 `/api/news-mcp/mcp`。配置服务密钥，证实百炼能将每次请求中的可信令牌转发为 `X-News-Context`；证实模型无法覆盖上下文范围，再设置 `NEWS_MCP_CONTEXT_VERIFIED=1`、插件 ID 和 MCP 开关。必要时按本应用实际协议调整候选 token mapping，不降级为仅凭静态密钥信任 article_id。
6. MCP 模式完成真实工具读取证据、引用字段与至少 10 篇内容核查，再按方案备份/构建/迁移/验证/开放入口；当前不得使用仅前端热更新包上线本功能。ESA 尚未适配应留明确提示。
7. 首期验收后开展 D：后台审核、发布与撤回、过期规则；再确认解读库 API 版本和管理权限开展 E。不能用模型调用 Key 替代知识库管理凭据。
