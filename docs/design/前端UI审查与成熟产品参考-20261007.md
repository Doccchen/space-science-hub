# 前端 UI 审查与成熟产品参考

日期：2026-10-07。目标：简洁、直观，让用户更快看新闻、提问、找到资料。本轮是设计审查，不修改前端代码、不部署、不调用收费 AI；后台管理保持现状。

审查了当前 index、新闻/资料/AI 脚本及全部有效样式层，并查看已有本机截图：`artifacts/frontend-refinement/news-1280.png`、`filters-390.png`、`artifacts/glass-theme-baseline/library-after.png`、`artifacts/ai-preview/home-after.png`。这些是旧本机快照，部分名称、透明偏好开关及假数据已被后续代码替换，不能视为当前线上截图。关于布局的判断同时核对当前源码，不把旧截图中的旧名称或测试标识误判成当前功能。

## 总体判断

当前主要问题是装饰和容器层级偏多。三页共同使用大标题、英文装饰行、圆角外框、独立卡片和较长说明，造成任务入口偏低，页面更接近展示页。优化重点是让三页遵循各自的用途，同时统一品牌、色彩、字体与导航。

按“简洁直观”目标给出的主观初评约 6.2/10，不是用户测试结果：

| 维度 | 分数 | 判断 |
|---|---:|---|
| 方向一致性 | 6 | 浅蓝品牌统一，但宣传页式大标题与高频工具任务不完全吻合。 |
| 信息层级 | 6 | 标题突出，筛选、状态、提示和内容之间仍有竞争。 |
| 细节完成度 | 7 | 焦点、空态、错误态、断点和阅读字号已有基础；样式覆盖层较多。 |
| 操作效率 | 6 | 新闻来源列表较长，AI 输入随历史下移，资料封面占用较多浏览空间。 |
| 设计表达 | 6 | 有蓝色品牌辨识，但三页大量复用相同玻璃卡片，任务差异不明显。 |

保留：三项主导航、清晰选中态、新闻真实来源/日期和既有分页、阅读弹窗及返回位置、资料搜索/分类/直下入口、AI 按需展开的检索资料、已实现的加载/失败/无结果反馈。无需追求更复杂的视觉创意。

## 七项优先优化

### 1. 首屏直接进入任务（高优先级）

当前新闻页大标题是“看见航天动态，读懂背后的科学”，AI 页在提问前有页面标题、欢迎标题、说明及推荐问题；资料页在书目之前也有多层标题与工具条。

建议统一导航为“航天新闻 / AI 问答 / 资料下载”，将“科普 Agent”改成普通读者容易理解的名称。新闻页用小标题“航天新闻”，资料页用“资料下载”，AI 用一个欢迎问题即可。移除重复英文装饰行；介绍保留一句，将额外说明放到关于本站。

导航高度建议约 64px，页面标题 24–28px，顶部间距 20–24px。这些是本站设计建议，不是外站测量值。空白应服务分组，不让正文或输入框被连续宣传区推到折线以下。

### 2. 新闻改为易扫读的列表（高优先级）

当前一条元信息同时显示来源、完整日期、机构类型、地区/国家发布主体、原始语言和停用状态；下方又有标题、阅读模式、原文链接及阅读按钮。每条独立大圆角卡片的内边距和底部操作行进一步增加高度。

建议保留现有左筛选栏，结果区改成更紧凑的列表：标题是主入口，元信息首先显示“来源 · 日期 · 语言”，地区、发布主体和详细状态按需展开。标题 18–20px、行高约 1.5；列表行上下间距 16–20px，分隔使用细线或轻边框。真实且可展示的摘要最多显示 1–2 行；原文链接稿不凭空增加生成摘要。

本站可读内容：标题打开阅读弹窗，次要操作“查看原文”。只有原文入口的内容：标题打开原文，旁边显示外链标记。底部保留一个明确的阅读状态，避免同一条重复出现多个等价链接。

不为了像新闻门户而给全部稿件增加图片、人工“头条”或“热门”标记。现有内容缺少对应图片授权或真实阅读量时，文字列表更稳妥。发布时间缺失、仅日期或未标时区等真实差异继续保留。

### 3. 新闻筛选采用渐进展开（高优先级）

桌面侧栏宽约 232px，来源当前整组全部列出、可内部滚动；初次用户需要读很多机构名及采集状态。既有移动端已经默认折叠筛选，保留这一改进，不重复声称它仍默认展开。

建议类别继续四项单选；来源先显示“全部来源”和少量常用来源，再提供“更多来源”。历史/停用来源仍可找到，不能因折叠而使已入库新闻不可筛选。当前选择必须在顶部清楚显示并可一键清除。

“每页 20 条”固定成默认值，把修改条数和指定页跳转收进次级菜单。保留底部页码，不改成无限滚动。“最近采集成功、来源未启用”等技术状态收到“更新状态”说明中，故障和上一筛选残留状态仍需清楚提示。

### 4. AI 分成开始提问与持续对话两种布局（高优先级）

当前输入表单位于 ai-thread 后，历史越长，下一次提问越靠下；用户和助手回答都使用完整大边框卡片。页面下方还有跨页资料库推荐。

建议空状态只保留欢迎问题、输入框及 2–3 个真实覆盖范围的示例。示例点击后填入输入框，沿用发送前可编辑的行为。知识库已经扩展，不应由 UI 独自假定仍只覆盖固体发动机；示例问题需根据实际已发布服务关联的资料核对。

对话开始后，阅读区居中约 720–800px；用户问题使用轻背景，助手回答直接排在页面上，用留白区分轮次。输入框固定在阅读区底部，线程预留对应底部空间，小屏考虑键盘及安全区；用户上滚阅读旧回答时不强制拉回底部。

新增“复制回答”“回到最新消息”。新对话入口始终可见，但不新增缺少持久化能力的聊天历史侧栏、文件上传、模型选择等控件。第一次分享/复制失败提供实际反馈，不显示虚假的成功状态。

### 5. AI 的依据与专业内容保持可读（中优先级）

保留“本次检索资料 · N 项”的折叠入口，书名与原始位置排列更紧凑。保留来源限制说明，可以把完整解释放入展开区；不照搬 Perplexity 的逐句脚注，因为当前协议没有经过核实的句子到依据映射。

现有安全 Markdown 只覆盖段落、标题、无序列表及代码等基本内容。航天问题常含公式、表格、单位和编号步骤，建议后续增加安全的公式/表格显示，代码块和长公式局部横向滚动；不让模型 HTML 直接进入页面。

隐私告知保留在输入附近一行，例如“请勿输入敏感信息”，完整的数据发送及保留说明按需展开，不能隐藏告知。达到轮次/额度/过期时提供明确的下一步。只有取消前端等待的能力时，按钮不能承诺终止上游生成或停止计费。

真实流式输出需后端支持；现有 /api/ai/ask 先收集答案再返回 JSON，不能仅用打字动画冒充真实生成过程。

### 6. 资料页以书名和下载为中心（高优先级）

当前桌面四列、封面约 2:3、每本独立大卡片；窄屏通常两列，359px 以下转一列。大封面加标题、作者、格式大小和按钮会形成较长的列表。不是所有手机都只显示一列，本轮建议基于当前有效 CSS，而不是遗留资源样式里的旧断点。

建议桌面仍保留简洁书目网格，但收小封面、降低卡片边框和阴影；下载按钮紧邻格式/大小，并统一位置。首次打开优先看到书名与获取入口。手机改成书目行：“60–80px 宽缩略封面 + 书名/作者/分类/PDF/大小 + 下载入口”，长书名正常换行、作者可次要显示。无需新增会挡住直接下载的详情弹窗，也不恢复之前取消的书籍介绍。

搜索和分类合并成紧凑工具栏，保留全部分类与当前结果数。无封面项采用简洁的 PDF 占位，不在图片占位区再完整重复一次长书名。格式/大小使用普通读者可理解的一致显示口径；若沿用二进制单位就保留 MiB，不仅替换字样为 MB。

可在第二阶段增加“默认顺序 / 书名 / 文件大小”排序。默认顺序保留后台排序；其他排序必须作用于整个筛选结果后再分页，不能只排列当前 12 项。前台不能自行声称文件已验证可下载，后台 HEAD 检查也不能替代内容/授权判断。

### 7. 统一可读性与状态表达（中优先级）

继续保留星知航品牌和蓝色识别。背景以浅灰/浅蓝纯色为主，正文白底；减少全屏渐变、模糊与逐条阴影。控件圆角约 8–12px，外层分组少用重复边框；主要蓝色只用于选中、链接和关键操作。

正文约 15–16px，元信息通常不低于 12–13px；移动正文不靠缩字号解决拥挤。点击热区维持约 44px，焦点、键盘操作、对比度、加载/失败/无结果继续保留。功能名使用中文；箭头与新窗口标记遵循相同行为，装饰性 ↗ 不用于会留在原页的普通按钮。

普通用户不需要看到开发组件参考链接和重复测试标识；相关内容可放到开发文档或关于页更次要位置。新闻及资料数据真实限制、隐私、来源和下载用途说明仍保留。

## 建议的页面结构

| 页面 | 从上到下的结构 | 主要操作 |
|---|---|---|
| 新闻 | 公共导航 → 简短页面标题 → 左侧筛选/右侧最新列表 → 页码 | 扫标题、选择来源、打开正文/原文 |
| AI 空状态 | 公共导航 → 一句欢迎语 → 输入框 → 少量示例/简短告知 | 输入问题并发送 |
| AI 对话态 | 公共导航/新对话 → 居中回答 → 底部输入框 | 读答案、查资料、复制、继续提问 |
| 资料 | 公共导航 → 简短标题 → 搜索/分类/结果数 → 紧凑书目 → 页码 | 找书、核对格式大小、下载 |

## 实施边界与顺序

第一批：精简重复大标题/装饰行，统一导航名称，压缩新闻元信息与重复动作，优化来源折叠，资料封面和手机书目布局，AI 输入定位与消息层级。主要是前端调整，保留现有 ID、API、新闻阅读状态、分页快照、资料下载和 AI 用量规则。

第二批：新闻全库关键词搜索、资料全结果排序、可筛选的语言/格式（如果资料确有多样性）、公式与表格显示。需要相应 API/渲染支持后再显示控件。目前新闻列表 API 没有关键词 q，资料 API 没有排序参数；不要做只筛当前页的假搜索或假排序。只提供 PDF 时不增加没有作用的“格式筛选”。

第三批：确有需要再增加真实流式问答、独立文章阅读 URL、历史会话或更多个性化。现阶段无必要加入聊天文件夹、登录账户体系、下载热度榜、推荐算法、大图轮播或复杂主题开关。

三个快速改进：去掉英文装饰行并缩短新闻标题区；精简每条新闻的冗余元信息；让 AI 输入框在长对话中始终可达。后续以实际桌面和手机画面核对上述目标，而不是依靠“看起来更高级”的主观描述。
